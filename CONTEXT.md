# agent-board

A desktop app that shows coding-agent sessions (Claude Code, Codex, plain shells) as objects on an infinite board, so one window replaces a pile of terminals.

## Language

### The board

**Board**:
The single infinite canvas a user works on. Holds zones, tiles, board items, connectors and edges.
_Avoid_: canvas, workspace (terminal multiplexers own "workspace")

**Zone**:
A coloured region of the board, either bound to one local git repo, optionally scoped to a folder inside it, or a **group**, bound to none. Several zones may share one repo. An agent started in a bound zone works in its repo, but any tile can sit in any zone, or in none: where a tile sits is only where it is drawn. It is moved by dragging its tab or its bare body, its tiles and items with it, and its tab always fits inside it: the chips that don't fit fold into the tab's ⋯ menu. Shrinking a zone past its tiles moves only the tiles its edge cuts through, each the least distance into free space clear of the other tiles and items; a tile that still fits never moves, and the zone stops once a cut tile has nowhere to go.
_Avoid_: project area, group

**Project well**:
A **zone** under the Simplified design, where the app calls it a project: a neutral well with a hairline, its colour only in the dot before its name, then how many of its agents need the user and a count of the rest by **status**. It has no tab of controls: every control of the Classic tab and ⋯ is in its ⋯ and its right-click menu (Project options › there is the whole ⋯), both from the one menu model. A repo, a group and a clone look the same; a fill set in ⋯ tints the well. Show technical details adds its folder at the end of its heading.
_Avoid_: project tab

**Repo zone** / **Folder zone**:
A zone bound to a whole repo, or to a sub-folder such as `apps/web`. In a folder zone the agent's worktree is still the whole repo but its working directory starts at the folder. A repo with no commits yet works too: its agents' worktrees are on branches with no commits either, or, where git is too old for that, its agents work in its own checkout; nothing is committed for the user.

**Group** (unbound zone):
A zone with only a name and a colour, bound to no repo: what the Zone tool makes by default, drawn with a dashed outline and a neutral tab. It holds notes, shell tiles and agents of any repos, each agent keeping its own. It can start agents from the same New agent dialog as a repo zone (task, name, harness, model, role), with a **Repo** field first: the **default repo** if it has one, else the last used repo, with its base and new branch folded under it, or a scratch repo. It can be bound later from its tab: **Open as repo** binds it to an existing repo, or to a folder in one; **Open as project** binds it to a new or empty folder, where the app runs `git init` and makes an empty first commit; either way it becomes a repo zone or a folder zone. It can be given a Linear team or a GitHub repo as its tracker without a repo. Any zone can be **unbound** again: it goes back to a group with no repo or default repo, keeping its tracker (taken away on its own from its tracker dialog), so its issue cards stay and still start agents, and its agents and shells carry on where they are. An **orchestrator** makes one too (`agent-board zone add --group`), placed as the Zone tool places a zone, beside its own zone and never inside another, marked as made by it and letting no agent orchestrate: it renames, resizes and removes only the groups it or its crew made (no zone inside a zone).
_Avoid_: empty zone, logical zone

**Default repo**:
A group's optional repo, or folder in one, shown as a soft chip on its tab. The Repo field of New agent in the group starts on it (change it there), and a shell made in the group starts in it. It doesn't bind the group: agents dragged in keep their own repos.

**Repo field**:
The first field of New agent where no zone gives the agent a repo (a group, or an agent dropped on bare board or started from an issue card there). A menu of the group's **default repo** (tagged so, and preselected), the recent repos (the last used preselected otherwise), Browse… for any folder, or a **scratch repo**, or, in a group with no default repo, **No repo** (its **group folder**), with its base branch and new branch folded in one line under it (for a **reviewer** that picked an agent to review, the Reviews field decides instead). The branch defaults to one made from the agent's name or its issue. A repo an agent starts in from there becomes a recent folder. A repo zone has no such field.
_Avoid_: repo picker, repo dialog, wizard

**Orchestrator role**:
The Orchestrator entry of New agent's role chip: a named role `orchestrator`, started with the scope `zone`, its task filled in from its template (the zone's, else the app's). A **Checkout** row picks where it works: the **main checkout** (the repo's own folder, on the branch checked out there; no worktree is made and none removed when it is deleted; the default) or a new worktree. Only the user's own start gives a main checkout; the agents an orchestrator starts get worktrees of their own. In a group with no default repo it starts on **No repo** in the Repo field, and the Checkout row says instead that it runs in the **group folder**; the agents it starts there pick their repo per task (`agent-board new --repo`), else run in the group folder too. Its tile's role badge is violet.

**Group folder**:
A group's own folder, outside git: the folder of the user's the zone was added for, when it was added for a folder outside git, else one the app makes in its data directory (`groups/<zone id>`) the first time an agent starts in the group with no repo (none given, and no default repo), and keeps across restarts. Such an agent is a **plain-folder** agent: it has no worktree or branch, the app runs no git there (no branch reads, pull requests, gate or checkout warning), and deleting it leaves the folder, which the group's other no-repo agents share, and which stays when the group is deleted. Its tile says it isn't isolated ("shared folder, no worktree"). New agent's Repo field offers it as **No repo**, and starts on it in a group added for a folder of the user's. **Make it a git repo**, in such a zone's menu, runs `git init` there (no commit) and binds the zone to it.
_Avoid_: scratch repo (that one is a git repo)

**Scratch repo**:
A new git repo the daemon makes for an agent with no repo to work in, with an empty first commit: a folder named from the agent's name as a slug (`-2`, `-3`… if taken) in the scratch folder, `~/.agent-board/scratch` (`$AGENT_BOARD_SCRATCH_DIR`). If the agent fails to start, it goes.

**Zone source**:
Where Add zone makes a new zone from, one tab each of its popover (opened by the **Zone tool**, `Z`, dragging out where the zone goes): **none**, a group, the tab it opens on; a **GitHub** repo gh can see, its tracker set to the repo's GitHub Issues; a **Linear** team, or one of its **projects** (named after the project), its tracker set to the team or the project, bound to a recent folder or left a group; a **Recent** folder a zone was made for before; or the **File browser**, which picks any folder with the OS picker and shows the path and the repo found there. A GitHub repo binds to a local copy the daemon knows (a zone's, a recent folder's, or a managed clone's), else to one the user points at with **Use my copy…** (the daemon checks the folder is a git repo, or in one, whose `origin` is that repo), else to a **managed clone**. **Find my local copies** is a link the user clicks to have the daemon look one level deep in `~/code`, `~/src`, `~/Developer`, `~/projects` and `~/GitHub` for repos with a GitHub `origin`; it never looks unasked. Its name and colour are set at the foot of the popover. Nothing is imported: a zone starts empty, and its tracker's issues are picked one at a time from its tab. The user's checkout is only where the zone is bound: agents still work in their own worktrees.
_Avoid_: import

**Managed clone**:
A GitHub repo the daemon clones for a zone, with gh, into `~/.agent-board/repos/<owner>/<repo>` (`$AGENT_BOARD_REPOS_DIR`). While it clones the zone shows its progress and a Cancel on its tab, and starts no agent. If the clone fails, is cancelled, or is cut short by the daemon going away, its folder goes, and so does its zone, unless sessions were moved into it meanwhile: then it stays, unbound.

**Tile**:
The board object for one session. Rendered by the active representation. Every tile can be dragged into any zone or loose onto the board, and keeps the place it is dropped (kept by the daemon, relative to its zone); a new one takes the first free spot. Where it sits changes nothing about its session. An agent's or shell's name is the user's to change, in place: a click on its name once its tile is the only one selected and a pause of about 0.6 s follows (as in Finder; a press that drags or a second click starts nothing, so a double-click anywhere on the tile, name included, opens it), the pencil beside it, F2 with the tile selected or its context menu. A shell split into panes can also label each pane, with the shell's name standing in without. Agents don't rename themselves (they set their **status**); renaming never touches the worktree, branch or session. An agent's tile is quiet at rest: its pill says how long it has been in its state ("running · 12m"; nothing in its first minute, nor while paused, starting or handing off), its clock chip the time to its next run ("in 2 h 10 m"), and its model and reasoning one tag (Max reasoning stays a tag of its own). Its corner actions (Expand, Pop out, ⋯) show on hover, focus or selection; its branch row only when the branch says more than its issue; a muted agent's bell sits beside its name. What it leaves off (its branch, who set its status, that its zone trusted its folder) is in its hover card. Settings › Board › Agent tiles can put each part it leaves off back on the Classic tile, one switch each; the Simplified tile is unchanged. Warnings always stay on the tile. A Simplified tile's grey line leads with the same times in words ("12 min · next run in 2 h").
_Avoid_: card (cards are issue cards), node

**Tile menu**:
An agent's tile has one menu, the same from its ⋯ and from a right-click on it, under both designs. It has ten rows at most:

- First, its next step when it has one: Go to its question (it asks for permission or waits on the user), Wake (paused), or Open review (a reviewer whose doc is in).
- Then its open and Pop out rows.
- The groups: **Run** (Interrupt mid-turn, Pause, Restart, Resume, Continue on credits, then Stop session; a paused agent's Wake leads the menu instead), **Settings** (Rename, Schedule, Link issue, Mute, Reasoning), **Review & gate** (its own pull request, the review rows, Show its implementer, reviewer or orchestrator, Run gate), **Arrange** (z-order, Align, Fold to a chip, the lead's pin, Connect to…), Ask Claude about it, and **Copy** (branch, worktree, session id).
- Last, Delete agent.

No row answers, approves or nudges the agent: Go to its question only opens it. With two or more objects selected, a right-click shows the selection's menu instead.
_Avoid_: More menu, context menu (the board's own)

**Calm tile**:
An agent's tile under the Simplified design: its name and its window controls (Fold to a chip, Expand, Pop out, ⋯ and Close, always shown), one grey line of what it is doing or asks, its **status**, and at most one button, filled only while it needs the user. Close never deletes: it stops a live agent, asking first, and folds a closed one to its chip; on a paused agent, one a restart stopped or one whose pane is a live shell it is disabled (Delete is in ⋯). Show technical details adds one mono line of its AI, model, branch, pull requests and raw state under it.
_Avoid_: card, calm card

**Shelves** / **shelf**:
An agent's sidebar in its **session window** under the **Simplified design**, and under **Classic** while Settings › Agents › Sidebar is Shelves (Full, the details strip, by default, stays a choice for one release), in place of the details strip: a row of icon tabs at the window's leading edge, on the left like the details strip, over the shelf shown and a two-line workspace footer (its branch, with its folder copied or revealed, and Collapse; its AI, model and role). A window opens on its **page**: a line with what the header's **status** leaves out (a flag's reason, Asks you, an exit code) and who started it and when, then the agent's own blocks and its **pins**, then From the board (only a crew member that needs the user and a pull request with failing or pending checks); until it writes a page, the board's Now (what it is doing or its last message, its linked issue) and one line saying the page is the agent's to write. The page's tab has the name and icon the agent picked, with the robot mark, or reads Now with the board's pulse. Made (its pull requests, the open one as a card with its checks, gate and linked issue; what it showed the user, its plan and documents; its **hand-off docs**, each row saying which it is, with their count), Crew (the agents it started and its subagents, an orange dot while one needs the user) and Setup (where it works: its folder now, branch, AI, model and role; around it: its linked issue, clock and gate). Records keep their recorded and guessed marks on every shelf. The **technical layer** under the Simplified design holds where it works and the gate; the footer always shows, its first line in plain words (its own copy, your checkout, your folder, or the branch it reviews) until Show technical details gives the branch. A shelf with nothing in it has no tab, and with the page the only shelf there is no tab row: once it has written a page, its name and icon are a header there. Narrower than 240 px the tabs show only their icons (Made's count stays, and each name is its tooltip), From the board's and Crew's rows a dot for a pill, and the page's blocks drop their robot marks to take the full width. Under Classic the window's controls are in its header while this sidebar is chosen: one state button and ⋯ for the rest. It is resized on the handle at its trailing edge with the details strip's one width; pulled below its least, with ⌘I, with the footer's button or with the Simplified header's details toggle, it collapses to its **rail**, one choice for every agent window, which an open one follows. The rail keeps the handle at its trailing edge: dragging out from it past the least opens the shelves again, and goes on resizing them as the drag goes on, and the right arrow on it opens them too. The expanded tile and shell windows keep the details strip.
_Avoid_: inspector (the sidebar it replaced), panel, details strip (Classic's Full)

**Rail** (of the shelves) / **peek**:
The **shelves** collapsed: a narrow column of their icons, with their names as tooltips: the page's in a ring of its progress (its first heading's, else its status line's; full and orange while it needs the user and has no page), Made's and Crew's with their counts (Crew's in orange, of those that need the user; Made's in the colour of a pull request's checks while they wait or fail). Clicking an icon opens that shelf as a **peek**, a short card over the terminal beside it, whose body scrolls; Esc, a click outside or an icon closes it, and its first button opens the shelves on that shelf. Not the details strip's icon rail, nor an edge's rail on the board.

**Expanded tile**:
A tile opened in place on the board: by a double-click (or Enter) when the **click setting** says Expand in place, else from its tile's hover Expand or its ⋯ menu. Still a board object, so it pans, zooms and drags (by its header) with the board, and is resized from any corner or edge, within a least and a greatest size; in a zone, not past the zone's padding. It opens at the size it was last let go at. A one-line header (name, state, branch, issue, pull requests; Maximise, Pop out, Delete, Collapse) over the session window's body: the details strip on the left and the live terminal, or a shell tile's panes, taking input. An external session's shows only its details. Several may be open at once, the last one clicked in front. It stays expanded until collapsed: Collapse returns it to its tile, as does Esc with the board focused (the one in front, then the next); a click elsewhere, on another tile or on another session's window leaves it be. The session keeps running. Its header's Delete deletes its agent or shell as the tile's ⋯ menu does, asking the same first (an external session's is Remove from board). Maximise opens its session window and Pop out its OS window, collapsing it, as a session is shown in one place at a time. Which tiles are expanded, their sizes, and which tile was dropped onto which, outlive a restart. Its zone grows to hold it, and what it would cover (tiles, items, zones) is pushed clear of it while it is open, live as it is resized. In a zone, and for loose tiles on the bare board (the loose tiles, never zones or notes, within a tile gap or two of it, and of each other, are its grid; two expanded tiles whose grids don't meet never move each other's), its neighbours move as blocks, not round it: everything right of it moves right, and every row below it (a row a little out of line still counts) moves down as a whole row (a tile below and right of it moves down only; a tall tile beside it moves right), each block by the one shift that takes its nearest tile in the way a gap clear of the expanded tile (as much as it grew, and nothing for a layout already made for its expanded size), so rows and columns stay whole and the zone grows to hold them; whatever is still in its way is then moved clear on its own. The tiles of a **crew frame** in it move as one, by one shift, so the crew keeps its layout and stays in its frame, which is drawn round where they are (one of them expanded, or dropped onto an expanded tile, the others move on their own, still in it); all of it goes back when it collapses, straight there (a tile's place never eases, so it stays fixed to the board as the board pans): drawn there only, never saved, unless the user drags it (resizing it from its left or top moves it, which is saved). Several expanded tiles, and the zones grown round them, are kept apart too, in board reading order, the first staying put and each next going to the clear spot nearest it: never by which is in front, so bringing one forward moves nothing. An expanded tile being dragged moves nothing out of its way. A tile the user drops onto another, one of the two expanded, may overlap that one, and only that one (but a shell tile dropped on an agent's becomes its tab, **Moving a shell**): the two stay where they were seen (the one dropped onto keeps the place it was drawn at), each still kept clear of everything else. The pair ends when either tile moves any other way (dragged again, nudged, undone, tidied, moved from a menu), collapses, is expanded again or goes. While a tile is dragged or resized, everything starts from where it was drawn as it began, so starting one moves nothing; what a resize grows into makes way from there.
_Avoid_: card, session card (cards are issue cards), panel, shelves (an agent window's sidebar)

**Folded chip**:
A closed agent's tile shrunk to one 34 px row: its harness mark, name and final state (ended, or merged once all its own pull requests are). An agent is closed when its session has ended and nothing is left of it: not one a restart stopped (it is resumed), and not one whose pane dropped into a shell that still runs, which keeps its tile and its Restart; live, idle and waiting agents are never folded. Closed agents fold by themselves and the fold is a view state: a click on the chip (or Unfold in its right-click menu, or expanding it any other way) unfolds it to its full tile, and Fold to a chip in that tile's ⋯ menu (under Arrange) folds it back; Delete agent in the chip's menu does what the tile's does, asking the same first. Which closed agents were unfolded outlives a restart, and an agent restarted forgets it, so it folds again when it next ends. The chip is the same board object, in the same place: it keeps its edges and rails, which attach to its smaller box, and it can't be resized. It is drawn centred in its tile's place, never saved lower, so an edge to a tile beside it is straight. An orchestrator's **arrange** lays a chip out at a chip's size. Undo follows an unfold and a fold.
_Avoid_: pill (the state pill is the part of a tile or chip that names its state)

**Folded zone**:
A whole zone shrunk to one **chip** (260 × 48 px, never wider than the zone) while it isn't needed, from the Fold button on its header or Fold to a chip in its ⋯ menu (both designs; Classic's on its tab beside ⋯, the first of the tab's chips to give way on a narrow zone, where ⋯ still folds it; the Simplified design's beside ⋯ in its heading). Folding pauses (**hibernates**) every agent in it that can pause and lets go its terminals and panes, so the memory they held is freed; an agent mid-turn, asking, or with an unsent message stays live, and the toast says which and why. Its tiles are not drawn. The chip shows the zone's colour dot and name, how many of its agents and **external sessions** need the user (in orange, so nothing urgent hides) and a count of the rest, its external sessions as "1 external", and in the Needs-you list its agents still show. Its ⋯ and right-click menu hold Unfold, Unfold and wake its agents, Rename and Delete. The zone keeps its saved place and size, and the chip is the room it takes meanwhile: **arrange** (the orchestrator's, and ⇧L) lays it out at the chip's size, so its neighbours close up round it, and a tile put loose on the board keeps clear of the chip only. **Unfold** puts it back at its size, first moving the zones, and the agents and shells loose on the board, that have come to sit where it opens: whole rows, down or along, a gap clear of it, saved, and no step to undo (an undo would put them back under it). Notes, shapes and text loose on the board stay where they are. Unfold wakes no agent: its paused agents stay paused until woken one by one, as if paused by hand. Unfold and wake its agents wakes the agents this fold paused that are still paused, and none paused before it, by the user or an orchestrator. Asked for an agent in a folded zone (the sessions list, search), the board shows its chip. A tile dropped on a chip stays loose on the board rather than joining the zone. Remembered across restarts.
_Avoid_: collapse (a zone's tab chips that fold into ⋯ are the **tab fold**), minimise

**Tidy**:
Laying tiles out in neat rows, in board reading order (by rows, then left to right): a zone's, from its tab's Tidy button or ⋯ menu, keeping its width and fitting its height to them, round its notes and cards; or the tiles loose on the board, from the board's context menu, in a grid about square from the top-left of where they are, clear of zones and items (from where the first lands, when one is in the way of that corner, so tidying again moves nothing). An expanded tile is laid out at its expanded size, so the others go round it. Unlike the room made round an expanded tile, it is saved, and one undo puts it back. An orchestrator's **arrange** is its own kind of tidy.
_Avoid_: auto-layout, sort

**Board background**:
The pattern drawn on the desk behind the board's zones and tiles, one choice for the app, picked in Settings › General › Appearance and heard by every window: **Standard** (dots under Classic, plain under the Simplified design; the default), **Fine dots**, **Large dots**, **Lines**, **Isometric** (dots on a triangular grid), **Vignette** (plain, darker towards the edges in light and dark) and **Plain**. Each is a CSS pattern, in the text colour at a low mix, so it reads on every theme and design and stays quiet behind tiles. The dotted ones, Lines and Isometric move and scale with pan and zoom (left out below 30% zoom); Vignette stays still. The square ones take the snap grid's gap: Lines as is and Large dots doubled, so a dragged tile's corner lands on a line or dot; Fine dots are half of it, a denser grid whose dots sit between the snap points; Isometric can't match it, and tiles still snap to the square grid. A swatch of each is in the picker.
_Avoid_: wallpaper, theme (that is the colour set)

**Board arrange**:
Laying out the board as a whole, never what is in a zone: from the board's context menu (**Arrange the board**) or ⇧L, or by an orchestrator of the whole board, such as the **Captain** (`agent-board arrange board`). Whole zones, at their own sizes and with everything in them, go in rows in reading order, top-aligned, from the top-left of where the zones are, a Roomy gap apart; the agents and shells loose on the board go in rows a gap below them. Notes, shapes and text loose on the board, and other sessions' tiles, stay where they are, and what moves keeps the gap from them: a zone that would cover one goes right past it, or its whole row goes down below it, whichever is nearer, so each row stays top-aligned and arranging again moves nothing. A zone is laid out at the size it is drawn but saved at its own, so the room round an expanded tile is never saved. Nothing runs it by itself. Saved, and one undo puts it back.
_Avoid_: tidy (that is a zone's tiles, or the loose ones where they are), arrange (that is an orchestrator's zone)

**Arrange**:
An orchestrator laying out the tiles of its zone that it may move (`agent-board arrange`), compact tiles on the zone's grid so lanes line up, and every lane, row and column only as big as what it holds: itself, the zone's shells and the clocks it or its crew made (never the user's own, which stay put) first, on the top row (the clocks in the order they were made, so where they were never decides where the lanes go), then a **lane** (a cluster) per issue, or per unit of work joined by edges or named by the ticket in its branch (no box round it; an agent another agent started is in that one's unit, unless that one is a **lead**, or the two are on different tickets, or it reviews another agent), a row each: a text label naming it in the first column; then a column per **slot**, the same in every lane, so compact lanes line up on the grid (a rail, or a wide tile, spreads only its own lane): the implementer (and whatever else does the work), the reviewer (whatever reviews another), the follow-up reviewer, a second of one slot taking a column of its own and a slot no lane uses taking none; then, right after the lane's own last tile so a short lane leaves no run of free slots, an **agent note** by the orchestrator saying where each of its agents stands (the status line it set, else its latest STATUS, else its state, and its pull request's number and title; never its prompt). Fix rounds stay on that pair, and there is no card for its pull request, which its tiles' PR chips already show (one an earlier arrange made goes). Wherever an edge joins two agents, a rail's room is left past each tile its **rail** runs by, and above each row it crosses (as a grid, a unit whose tiles edges join is laid out exactly as in rows, and only the tiles no edge joins fill the grid round it, clear of its rails), so the rail has room for its token and label at either end. Arranging again moves the label and note with their cluster, never stacking new ones, keeps a note's text once anyone edits it, takes an agent note the orchestrator put beside one of its agents' tiles, on any side, as that cluster's note, and replaces an old unedited sticky cluster note with an agent note. The orchestrator's own agent notes about itself (it is in no lane) are laid out as a block of rows, four across, its top at the orchestrator's tile and right of everything else laid out, never stacked above the tile and never pushing a lane down: the first tile is always at the zone's top padding, the zone grows wider for the block rather than taller, and shrinks to fit with no empty band above or between lanes. The block's width never depends on the zone's, so arranging again moves nothing. A note the user turned stays where it is, like the user's own. By role or state it is a row each, an arrange by issue's parts lined up beside them. Each lane's note is as tall as the app measures its text (but one the user sized keeps its width and height, and the lane is laid out round it; a note there already that is to say something new says it first, and the arrange waits a moment for its measure; a refused arrange puts its text back, and its size, unless the user resized it meanwhile; the app measures every note, on screen or off), and what it lays out round is as big as it is drawn; with no window open or in front, or a note not measured in time (a new lane's), it estimates and says `unmeasured`. A tile expanded in place counts at its expanded size, so its lane is taller and its column wider; so it does for everything else an orchestrator lays out (`move`, where a new crew member goes, groups). What it may not move stays put and the rows keep clear of it, and the zone then fits what it holds, its margin round it: grown, or shrunk once it was left too big. Lanes can be laid out as rows (the default), as **columns** (a column each, its label and note in its first cell), as **cards** (a block each, two or three across, a free grid column and row between them) or, never by default, to **wrap** (a lane each below the one before, its label over its note in its first column, its tiles in slot order wrapping onto a new row after four, each lane's columns its own; by role or state, as rows), as **masonry** (each lane as wrap lays it out, in the shortest of as many columns of lanes as best fit the app's window, or the zone's width with none open) or as a **treemap** (each lane a block sized by its tiles, packed to the app's window's shape, or 16:10 with none open, never the zone's own, which it then fits; none overlapping another); masonry and a treemap pack each row by role or state as a lane. Lanes go in the order their work started, so a new one goes last and the others stay put. What an arrange was asked to group by and how to lay out, and whether to arrange by itself (**auto-arrange**: after every agent it starts, note it adds and agent it closes), are kept per orchestrator. An arrange prints its **zone map**. The same board always arranges the same way. A reviewer it starts on a clustered agent's branch joins that cluster. With `move` (a tile or note to a zone, exactly at a grid cell or beside another where the app draws it, what is in the way moving aside) and its **notes** (sticky notes or text it made; near an agent, in its cluster's slot), it keeps its crew tidy. Each is in the **activity log**.
_Avoid_: tidy (that is the user's, by reading order), auto-layout

**Spacing**:
How far apart a zone's **tidy** and an orchestrator's **arrange** in it put things: **Compact**, **Normal** or **Roomy**, each a tile gap, a lane gap (the perch above a row's tiles in it), a zone padding and a rail's length (8 / 32 / 12 / 176 px, 16 / 40 / 20 / 192 and 32 / 64 / 32 / 224), kept in one table. Tiles in a row are never closer than the board's 16 px dots. Each zone keeps its own, picked from the ▾ beside its tab's Tidy button (or ⋯ › Spacing), which saves it and tidies the zone at once; its orchestrators' arrange and auto-arrange use it, and its **zone map** measures gaps past it, in its own grid's slots. A new zone takes the default in Settings › Board › Tidying (Roomy until changed); zones made before there were spacings keep Normal. Changing a spacing moves nothing else by itself.
_Avoid_: density, padding (one of its four gaps)

**Layout mode**:
How a zone draws what it holds, kept on the zone and picked from its tab's Tidy ▾ or its ⋯ › Layout and spacing (the project menu's Layout under the **Simplified design**), or by an agent in its scope (`agent-board zone layout`, the MCP `zone_layout` tool): **Free**, each tile where it was put, as every zone was, **Status shelves** or **Clusters**. Every zone is Free until someone picks, a new one too: nothing lays a zone out so by itself. Only where things are drawn changes, never a tile's saved place, so a zone set back to Free shows as it was, and its tidy, arrange and zone map still read that free layout.
_Avoid_: arrange layout (rows, columns, cards: how an orchestrator's arrange lays lanes out)

**Status shelves**:
A **layout mode** that draws a zone's work by status, on four shelves left to right: **To do**, **Doing**, **Waiting** and **Done**, each headed by its name and count, under a head row of the zone's **leads**, then its shells. Each unit of work (an issue, the ticket in a branch, or agents joined by edges, a review, or as the agents an agent that is no lead started, as an **arrange** lanes them) is one **stack**. A stack is on Doing while one of its agents works, needs the user, or failed (as the daemon says; a stop is no failure, whatever its exit code), until its work is merged; on Done once its pull request merged; on Waiting while its pull request is open, waiting on someone who is neither the user nor the agent, even with all its agents closed; on Done once every agent is closed; on Doing again once an agent of it has finished a turn; and on To do while none has finished a turn and none waits on anyone. What needs the user goes first on its shelf. Done is one line, "N done · Show", until shown as chips. The shelves share the zone's width, Doing twice the others and one to three cards across; a zone too narrow for four puts To do and Doing above Waiting and Done. A shelved zone is drawn as big as its shelves, and not resized by hand. Its Tidy is off and an **arrange** of it is refused, since either would move tiles folded out of sight. ⌘K, Needs you and an agent note's Show agent fan out the stack of an agent folded into one, and bring it into view; its **ask chip** shows once its agent's stack is fanned out.
_Avoid_: swimlanes, kanban columns, lanes (an arrange's)

**Clusters**:
A **layout mode** that draws each unit of work's tiles together, at their compact sizes, side by side (in rows of their own when there are more than the zone holds across) in a dashed outline headed by its ticket, title and stage (and the agent notes folded into it), its tiles close together and the clusters well apart; work that is a single tile is its own group, with no outline or label. All under the same head row of **leads** and shells as **status shelves**, a pinned lead saying so. What needs the user goes first, nearest the top-left and outlined in orange, then Doing, Waiting and To do work, each by when it started, packed in rows within the zone's width (the zone grows downward, never wider); Done's work folds behind one line, "N done · Show", newest first once shown, as on its shelf. A cluster has nothing to open: its tiles are already drawn. The tiles are themselves, live, but are not dragged, and the zone's Tidy and an **arrange** of it are off, as on shelves.
_Avoid_: lanes (an arrange's), groups (zones bound to no repo)

**Layout rule**:
How a zone lays its tiles out by itself, kept on the zone and picked in the same Layout list as the **layout modes** (or with `agent-board zone layout`, the MCP `zone_layout` tool): Off, as every zone, a new one too, starts, or **Lanes by ticket**, an **arrange** by issue of the zone's tiles. Unlike a layout mode it moves tiles' saved places: the daemon lays the zone out by it once when it is picked, and again a moment after what the zone holds changes (a tile comes or goes, an agent's ticket, role, name or who started it changes, an edge joins two agents, the user resizes the zone), never for a tile's place or an agent's state. It keeps the size the user gives the zone, and only grows it to fit. A zone with a rule is Free, its Tidy is off, and an orchestrator's arrange of it any other way is refused. Picking a rule, or leaving one, is one undo step that puts its agents and shells back where they were.
_Avoid_: auto-arrange (an orchestrator's, after what it starts)

**Placed by hand**:
A tile the user moved within, or into, a zone with a **layout rule** (dragged it, nudged it with the arrow keys, or resized it from its left or top edge): the rule leaves it where it was put, and a pin beside its title says so. Its right-click menu's **Put back under the rule** lets the rule lay it out again. A tile that leaves the zone, and every tile when the zone's rule changes, loses the mark, as does a tile that closes. An agent's moves never set it, wherever they put the tile, and a clock is never marked.

**Stack**:
One unit of work's agents in a zone on **status shelves**, drawn as one card: its ticket and title, how many agents it holds (when more than one), a line per agent (its role or name, its status in a word, what it asks or is doing; four, then "+N more"), and its pull request and the agent notes it stands for (a lead's note about one of its crew is that agent's). On Waiting it is a one-line row saying what it waits on, on Done a chip. A click (or Enter) fans its tiles out below the shelves, in the free space there, from the card's left, and the rest of the zone steps back with the card in front, as Stage Manager does: no card is covered and nothing on the board moves for it, and another click, a click on the zone, or Esc folds them back. A line of a card says Needs you only as the Needs-you pill counts it; Doing's heading counts them. A lead pinned top-left says so over its tile.
_Avoid_: pile, group, cluster

**Lead**:
In a zone on **status shelves**, an agent that orchestrates there: one with the orchestrator role, the **Captain**, or one with no role that started an agent other than its own reviewer (every agent the user starts may orchestrate; only these lead). An agent with any other role, custom ones included, is no lead: they go in its unit of work, its stack. A lead is pinned top-left, in the zone's head row, never in a stack, and each agent it started is a unit of its own, never in the lead's; its right-click menu's **Free from top-left** makes it a stack like any other (kept for every window), and **Pin top-left** pins it again.
_Avoid_: master, head (the head row is where leads are drawn)

**Zone map**:
What an orchestrator reads to check a zone's layout without a picture (`agent-board zone map`, the MCP `map` tool, printed after every **arrange**): a line per lane with a cell per slot, each tile's ref, name and state, a free slot as `·`, the orchestrator and whatever is in no lane on the top line; then where the next lane goes, which lanes are all done, and a lint line naming tiles on top of each other, the widest gap in a lane (in slots), a lane's label or note stranded away from the tiles it belongs with, a zone mostly empty (a band of grid columns or rows right across it with nothing in it, however far its far corners reach) and tiles (and the crew's clocks) not where an arrange as set puts them (one no arrange places, off the grid) or out of their lane. With `--boxes` it is a box picture instead: the zone in characters, about one to 40 px, overlaps shown as `#`. Things are where the app's window in front draws them (a tile pushed aside by an expanded one, a text item as big as its text), the lint holding them to where they are saved; with no window open it says `unmeasured`. It moves nothing.
_Avoid_: screenshot, ASCII map

**Zone screenshot**:
A PNG of a zone for its orchestrator (`agent-board zone screenshot`, the MCP `zone_screenshot` tool), for when the **zone map** isn't enough: the app draws the zone in a hidden window, as the board draws it but the zone alone (no panel, session window or chrome over it, nothing outside it) and with every terminal's text hidden, never moving the user's view; at 1×, or smaller for a zone over 1,568 px a side or a picture over 3.5 MB. Its **lo-fi** style is a plain drawing from what the daemon knows: each tile and note as a labelled box, edges and connectors as straight lines. Needs the app open.
_Avoid_: capture (the mechanism, not the thing)

**Session window**:
The window that shows one session, or a shell tile's panes, over the board (or popped out into an OS window of its own): what a double-click on an agent's or shell tile opens by default. A single click only selects the tile. On the board it is resized from any edge or corner, within a least and a greatest size and inside the board, and Maximised and Restored from its header (or a double-click on empty header space); one global size and place is remembered across restarts, and a pop-out's OS window size is remembered too. Its header steps through the other sessions of the tile's zone, or the other loose ones for a tile in none, in board order (left to right, then top to bottom), with ‹ › and ⌘[ / ⌘], wrapping at the ends; the window swaps what it shows rather than closing. Its details strip opens collapsed to the icon rail in every session window, pop-out and expanded tile (⌘I, the rail's Show details or a drag out of the rail opens it; nothing carries open across windows), and is resized by dragging the handle on its border (at least about 200px, at most half the window; pulled below the least it collapses to the icon rail, ⌘I, and dragging out from the rail opens it again; double-click resets; arrow keys step it), one width remembered for every session window, pop-out and expanded tile, and shows the focused pane's **live folder**, where that pane's process is now (following `cd`, `~` for home, copyable, revealed in Finder), beside an agent's fixed worktree and branch, with an "Outside its worktree" hint when it has left it. Under the **Simplified design**, and under Classic with the Shelves sidebar, an agent's window has the **shelves** on the left instead, open or collapsed to their **rail** as last chosen in any window, which an open window follows.
_Avoid_: modal, dialog

**Seen**:
An agent whose session the user has opened (a session window, an expanded tile or a pop-out, or focused an open one) since it began its current ask: a permission prompt, a question or plan, or (with finished turns listed) waiting for input. Opening it also clears its **flag**. A seen agent drops its needs-you look on its tile (no orange outline, a calm pill), is read in the inbox, and no longer counts towards the dock badge, the dock's needs state or the menu-bar dot. The daemon keeps it, so every window and restart agree. The next change of its state (it works, or a new permission prompt) clears it, and it needs the user again. A click in the window it is open in sees that new ask again, so a long session kept open never piles up asks. Ended agents and the inbox's Dismiss are unaffected.
_Avoid_: acknowledged, read (an inbox item is shown read; the agent is seen)

**Click setting**:
What a double-click (or Enter) on a selected agent's or shell tile opens (a single click selects it): its **session window** (the default) or its **expanded tile**, picked in Settings › Board › Opening tiles. The tile's ⋯ menu offers the other one, once. An external session's tile, having no session window, always expands.

**Dock**:
The row along the board's bottom edge holding the **session windows** minimised or popped out into an OS window. Settings › Board › Opening tiles › **Dock** picks what it holds: **All** (Show everything, the default), **Pinned only** (Only what I pin) or **Off**, switching live in every window and remembered. With Pinned only the dock holds only the windows pinned with the pin button in a window's header (or unpinned from its pill in the dock); a pin is kept while the setting is on another mode. With Off there is no dock and no pin button. Whatever the dock leaves out is still reached: ⌘K lists it in its Windows group (under Classic too, once the dock is not Show everything), and the Window menu lists every minimised window under Minimised. The board's free space adjusts as when no window is minimised.
_Avoid_: tray, taskbar

**Switcher**:
The Spotlight-style search ⌘K opens (Ctrl+Shift+K off macOS) from any window of the app, the focus in a terminal or a web tab's page too: one field over the agents, shell tiles and zones. Before anything is typed it lists those that need you, then the most recently active, then the zones; typing ranks them in one fuzzy list, by name, then issue, branch, zone and what the agent asks. Its rows follow the board while it is open. On the board, ↵ flies the board to the tile (jumps, with reduced motion), pulses it and selects it, and ⌘↵ opens it as the **click setting** says; in the session window shown on the board, or an expanded tile with the focus, ↵ switches that view to the session, focus in its terminal, as ‹ › do. In a popped-out window, ↵ shows the session in that OS window instead. A session already out in an OS window of its own comes forward there, and the view it was picked from stays as it was. A zone picked is brought into view, the session window or expanded tile closed first; from a popped-out window, the board's window comes forward to show it. Once something is typed, the settings whose names (or the other words they go by) hold it are listed under them, under Settings, and one picked opens the **Settings window** at its section. With no session or zone matching it offers a new agent by that name, first and picked, above any settings found. Esc, or a pick that finds nothing, gives the focus back where it was. The board menu keeps ⌘\, which opens it on its own filter; its Find button opens the switcher.
_Avoid_: command palette (it runs no commands), quick open

**Key registry**:
The one list of every key the app answers to (`keys/registry.ts`): for each, an id (`section.action`), its default chords (the platform's modifier rule applied: ⌘ on macOS; Ctrl on the board, Ctrl+Shift where a terminal can have focus elsewhere), where it works (board, tile, window, or terminal-safe), a label, and whether it was there before the registry (`today`), is `new`, or `fix`es an existing key. Handlers match presses against it, and the **cheat sheet**, tooltips and menu hints write keys from it.
_Avoid_: keymap, shortcut list

**Extended keyboard shortcuts**:
The setting (Settings › General › Keyboard; on by default) that turns the registry's `new` keys on. Off, the app answers only to the keys it had before the registry, plus the `fix`es, which correct bugs. Every window reads the same value.

**Cheat sheet**:
The overlay listing the registry's active keys by section, those for where it opened first (the board, a selected tile, or a session window), with a filter. `?` opens it on the board and ⌘/ (Ctrl+Shift+/ off macOS) anywhere, both `new`; the board's keyboard button opens it whatever the setting.
_Avoid_: help popover, shortcut help

**Representation**:
A swappable way of drawing tiles and subagents. v1 ships only **Hybrid** (calm tile + subagent characters). **Character**, **Token** and **Plain tile** are post-v1.

**Character**:
The small figure that shows an agent's or a subagent's state through its **pose**, on its tile: a bean body for Claude, a block body for Codex, in the style Settings › General › Design › Characters picks (Off draws none). The board draws the pose for the agent's state; the agent may set its own (see **Pose**).

**Pose**:
What a **character** is doing. The board has one for each agent state. An agent sets one of six for itself with its status (`set_status` `character`, `agent-board status set --pose`; `status poses` lists them), and an orchestrator for its crew: five working poses (thinking, running a tool, reading, writing, testing), drawn only in a turn and gone at its end or 20 minutes after it was set, and one resting pose (waiting on review), kept at its prompt until its next turn starts. The board's own states are drawn over it: a permission prompt, a question, a plan, a steps card, a flag, a problem, a usage limit, and whatever else its tile says **Needs you** for (on a Simplified tile, an open pull request of its own). The pose waits underneath (`poseShown`). With its pose it may give a face and a prop, each from a fixed list (`status poses`), drawn only while its pose is (`lookShown`); hovering the character says who set it.
_Avoid_: animation, mood

**Issue card**:
A kind of board item: a tracker issue as it was when picked (its ID, title, state and link), put in a zone from its tab's issue picker. Until an agent works on its issue it offers to start one; an agent linked to its issue is drawn fed by it, along an **issue brief** edge.
_Avoid_: ticket

**Issue brief**:
The coloured flow edge, labelled "issue brief" with a trigger icon, from an issue card to each agent linked to its issue. Drawn by the board from the card and the agent's linked issue; never stored, selected or deleted on its own. It is a curve that goes round the tiles, notes and expanded tiles between the card and the agent, 16 px clear, as a curved arrow does, its label on the line it takes; it is the plain curve when nothing is in the way or nothing is clear. Edges between agents are drawn as a **rail** instead.

**Board item**:
A whiteboard object on the board that is not a session: a sticky note, a text item, a shape, an image, a link card, an issue card, an agent note or a clock. It has a kind, a place, a size, a stacking order and data of its own kind's shape. Like a tile, it sits in a zone (and moves with it) or loose on the board, and dragging it in or out of a zone moves it into that zone or out onto the board. Kept by the daemon, so it outlives the app.
_Avoid_: node, widget, edge (an edge is a flow between agents)

**Sticky note**:
The first kind of board item: a coloured square of short markdown text (bold, italics, lists, https links) whose font shrinks to fit. Made by double-clicking bare board or a zone, the Sticky button, or `N`; by `agent-board note add` from the user's side; or, from the user's side, in each lane's note slot by an **arrange** (an orchestrator agent's arrange makes agent notes instead).
_Avoid_: note card, card (cards are issue cards)

**Agent note**:
A kind of board item an agent wrote, never taken for one of the user's sticky notes: a typed card of markdown (bold, italics, `code`, lists, https links) with a **badge** naming its agent (its harness's mark, its name and role) and the time it last wrote it. An orchestrator's `agent-board note add` (`add_note`) makes one, marked as made by it, unless it asks for `--kind sticky` or `text`; Ask Claude's answers are one too. It keeps who wrote it, so it still says so once that agent has gone. The badge, and **Show agent**, select the agent's tile, and a dashed **tether** leads from the note to it (drawn with every connection shown), straight, or square round the tiles and notes between them as an elbow arrow goes. A note an orchestrator writes about a crew member (its cluster's implementer, or the tile it was put beside) is tethered to that agent, never to the orchestrator, whose badge alone says who wrote it. The user moves, resizes, deletes and edits it as a sticky; one they **resize** (by dragging a corner, or `agent-board note edit --size <w>x<h>` and the MCP `edit_note` size, 200×96 to 1200×1440) keeps that width and height through an **arrange** (the lanes are laid out round it), a rewrite of its text and a restart, and no longer grows to its text, which scrolls under a "↓ more" cue until read to the end; once they edit it, it says **edited by you**, until its agent writes it again. It is drawn as a document card (the default) or the agent's terminal cut out, as Settings › Board › **Agent notes** says, every note switching at once.
_Avoid_: AI note, bot sticky

**Image**:
A kind of board item: a PNG, JPEG, GIF or WebP, pasted from the clipboard or dropped on the board, at most 20 MB. Its bytes are kept by the daemon in the **image store** (files named by the SHA-256 of their bytes, outside SQLite); resizing keeps its aspect ratio unless Shift is held.
_Avoid_: picture, attachment

**Link card**:
A kind of board item made by pasting one https URL on the board. It shows the page's title, domain and favicon, fetched by the daemon in the background (best effort, no scripts run, 5 seconds at most; the bare URL shows meanwhile and if the fetch fails). For a Linear or GitHub URL that a zone's tracker covers it also shows the issue or pull request's state. Clicking it opens the URL in the browser.
_Avoid_: bookmark, embed

**Text item**:
A board item of free text with no background, in heading 1, heading 2 or body size, with bold, italics, alignment and a **colour slot** (or a fixed colour). As wide as its longest line while typed, until it is resized, when it keeps its width and wraps. Made with `T` (or the Text button), then a click. Removed if left empty.
_Avoid_: label, text box

**Shape**:
A board item that is one of 43 diagram shapes (flowchart, architecture and UML: a process, a decision, a database, a cloud, a class, an actor and so on), with a fill (or none), a stroke and text inside it, each in a **colour slot** or a fixed colour (under it, for a figure such as an actor). Typed in by a double-click or Enter, the text can be aligned left, centred or right, set at any font size and in mono, and the shape grows taller to fit it, never shorter: text is not cut off, and a shape made taller by hand keeps its height. A **Class** and a box **Interface** have **sections**: the name, then the attributes and the methods, each under a rule and typed in on its own (a double-click types in the one under the pointer; Tab and Shift+Tab move between them while typing). The attributes and methods are set left-aligned, in mono unless Mono is turned off, and a first line such as `<<entity>>` in the name shows as its stereotype (an Interface shows `«interface»` until its name gives another). The name and the sections share one text's length. UML's lollipop is the **Provided interface** shape. Picked from the **shape picker** under the Shape button (`S`), then a drag to size it, or found by name or another word for it with `/` at the pointer. The flowchart's connector symbols are the **On-page reference** and **Off-page reference** shapes (ids `circle-connector` and `off-page`), never a **Connector**, which is an arrow between objects. Draws below tiles, so one can frame a group of agents without covering them. An orchestrator asked for a diagram draws shapes with `agent-board shape add` (the `add_shape` tool) and joins them with `agent-board connect` (`connect`), or draws a whole Mermaid diagram with `agent-board diagram add` (`add_diagram`), and reads them back with `show`, `tree` and `zone map`, or as Mermaid with `diagram export` (`export_diagram`). Pasting a Mermaid flowchart or class diagram on the board draws it as shapes and connectors, laid out as Mermaid lays it out; **Copy as Mermaid** on a selection with shapes in it copies them, and the connectors between them, as Mermaid text.
_Avoid_: node, frame

**Colour slot**:
One of the twelve theme colours a text item, a shape's fill, outline and text, or a connector is drawn in: Accent, Ink, Grey, then the theme's Red, Orange, Yellow, Green, Teal, Cyan, Blue, Violet and Pink. An item keeps the slot, not the colour, so switching theme recolours it. A shape's fill is its slot tinted into the tile, or the tile itself; a new shape is Accent on the tile. A **fixed colour** (`#` on the style bar, or any `#rrggbb` from the CLI or MCP) is the same in every theme. A colour saved before slots is read as the slot it was. Sticky notes keep their own paper colours.
_Avoid_: preset, palette colour, swatch (a swatch is the button that picks one)

**Connector**:
An annotation arrow or line between any two board objects: zones, tiles, sticky notes, text, shapes, images and link cards. A thin neutral line (straight, elbow or curved; solid or dashed; an arrow, a dot, a hollow triangle, a hollow or a filled diamond, or nothing at each end; a colour; an optional label in the middle, and one by each end, such as a multiplicity `0..*` or a role) that explains the board and never carries or triggers anything. Its **relation**, picked from its style bar, names a class diagram's relations and sets its ends and dash at once, read from `from` to `to`: an association (no ends), a directed association (an arrow), an inheritance (child to parent: a hollow triangle), a realisation (the same, dashed), a dependency (a dashed arrow), an aggregation (whole to part: a hollow diamond at the whole) or a composition (a filled diamond there); ends no relation has are its own, set one by one under **Custom ends…**. **Swap direction** (⇧S) turns it round, its end shapes going to the other objects and each end's label staying by its object. A double-click near an end types that end's label; elsewhere, the middle one. The labels and ends follow the line as it is drawn, round what it is routed round too. Made by dragging from a **connector handle**, it follows its two objects when they move, and is deleted with either. Kept by the daemon, in its own table. Selected, a straight or elbow one can be bent through points (kept from the middle of its two ends, so they move with its objects), a curved one bowed by the one **bow handle** on its middle, and either end dragged to another side of its object or onto another object, or put back if let go on nothing. An elbow or curved one with no bends of the user's is **routed**: it goes round the tiles, notes and other objects between its ends, 16 px clear of them (8 px in a gap too tight for that), and is drawn as before when nothing is in the way or no way round is clear; bending it by hand stops that, and **Route automatically** on its style bar takes the bends out again. A straight one never routes. In the app it is called an **arrow**, as in the chooser that asks whether one dropped between two agents is an Arrow or a hand-off.
_Avoid_: edge (an edge is a flow between agents), link (a link card is a board item), wire

**Connector handle**:
One of the four round dots, at the middle of each side of an object, that show while the pointer is over it or it is selected; while an arrow is drawn, or a selected one's end dragged, only the object the pointer is near shows them, grown. Dragging one onto another object, or onto its handle, joins the two with a connector; dropping on empty board makes a new sticky note there and joins that; dropping anywhere else does nothing. A zone is joined by its tab or a handle, since dropping in its body makes a note in it. Handles are **round** and sit on the middle of a side. One dropped from an agent's tile on another agent's asks whether it is an arrow or a **hand-off** (an **edge**), and with ⌥ held it is a hand-off at once; every other drop is a connector.
_Avoid_: port, anchor

**Rotate handle**:
The round grip under a board item selected on its own, or under the box round a selection of several, that turns the item (each item, about its own centre) as it is dragged round; Shift snaps the angle to 15° steps. The angle, its **rotation**, is saved on the item, undoable, and put back straight by Reset rotation (the selection's menu, or ⇧R). Only the user turns things: tiles always sit straight, and nothing on the board is drawn at an angle by itself.
_Avoid_: tilt (the old automatic lean, gone), spin

**Selection**:
The board objects picked together, by click, Shift-click, a marquee dragged on empty board (or inside a zone with Shift held, since a plain drag there moves the zone, or in **Box select**, B, where a zone moves only by its tab), or select all. It moves,
aligns, restacks and is undone as one, inside one labelled box. Delete, copy and duplicate act on its board items and
connectors only (Delete also on a selected edge); a session in it is never copied or duplicated from there, but is deleted behind one combined question, listing what happens to each kind (items stay undoable, sessions don't). ⌫ never deletes a session while the keyboard belongs to its session window, its expanded tile or a dialog.
_Avoid_: group (nothing groups objects for good)

**Ask Claude** (about a selection):
Asking an agent about part of the board: the selection's **Ask Claude…** (beside its label, in its right-click menu, or ⌘⇧A) opens a popover for the question, the agent's harness, model and role (`architect` by default), whether it may read the selection's zone's repo, and whether it may suggest edits. Nothing is sent until **Ask**. Then the daemon starts an agent with no worktree or branch of its own: in that repo's checkout itself, read-only (Claude in plan mode, Codex in its read-only sandbox), or else in the ask's own folder, outside git. Its first message is the question, the selected objects alone drawn at 2× as a PNG (`selection.png`) and its **diagram** (`selection.json`: each object as a node with a short id, its kind, text and box from the selection's top-left; the connectors between them; the zones they are in), both kept in a folder of the ask's own until the agent goes. Its first finished turn lands as an **agent note** to the right of the selection, saying what was asked, joined to the selection's rightmost object by a connector, with the agent's tile moved under it; later turns are answered in its tile only.
_Avoid_: AI review, architect mode

**Suggested edit**:
A change to the diagram an Ask Claude answer proposes, in a fenced `agent-board-suggestions` block at the end of its final message, which the note's text leaves out: a title, new shapes, and connectors between them and the selection's objects. It is drawn as a dashed **ghost** where it would go, with a chip to accept it (its shapes and connectors become real, as one undo step) or dismiss it; the note offers them all at once. Kept on the note until accepted or dismissed.
_Avoid_: proposal, patch

**Undo history**:
The board edits a window can take back and redo: making, changing, moving, resizing, restacking and deleting board items
and connectors, moving and resizing zones and tiles, and deleting zones (undone, each is the same zone again, bound to its repo if that is still there, with its tiles and notes back in it). Kept in that window's memory, at least 100 steps; it never
starts, stops or sends to a session.
_Avoid_: history (alone: a run history is a long-lived agent's)

**Alignment guide**:
A line drawn while dragging where an edge or centre of what is dragged meets one of something near it, which it snaps
to, as on Miro. Holding the command key drags without snapping, and **snap to grid** puts the corner on the desk's dots
instead.

**Theme**:
The app's whole look as one set of theme token values: its UI, the terminal's ANSI colours, how a sticky note's stored colour is drawn and the agent states' colours. The app's own are **Workbench** light (a dotted off-white desk, tinted zones, white tiles) and the dark **Warm graphite**; the rest come in **theme packs**. Which one shows is the **Appearance** setting.
_Avoid_: skin, style (a representation is a style of tile)

**Theme pack**:
A family of themes made from another project's palette, such as Catppuccin's four flavours or Gruvbox's light and dark: data, not code, credited in the picker under the family's name and in `THIRD_PARTY.md`. Every one keeps text at WCAG AA.
_Avoid_: skin, preset

**Settings window**:
Where every setting is: a window of its own beside the board, never over it, opened by the app menu's Settings… (⌘, on macOS), the board menu's Settings… row and the gear on the top-right island, which bring it forward if it is open. Its sidebar has seven groups, **General**, **Board**, **Agents**, **Alerts**, **Usage**, **Accounts** and **Advanced**, each opening to list its sections; a group's page shows each section's controls under its heading, and a section picked in the sidebar opens its group's page at it. Every control lives in exactly one section, kept in one table the window draws from. A search field atop the sidebar filters it to the sections that hold what is typed, in a section's or group's name, a control's label or the other words it goes by ("spacing" finds Tidying), across groups, and shows those sections on one page with the matches highlighted; ⌘K finds settings from the same table. It reopens on the pane it last showed, unless it was asked for another (a zone's "Default for new zones…" opens Board › Tidying). Written here as a path: Settings › Board › Tidying.
_Avoid_: preferences, settings panel, the board menu's Settings

**Appearance**:
The setting, under Settings › General › Appearance, that picks the theme: a mode, **Light**, **Dark** or **System** (the default, which follows the OS's light or dark mode, live), and a **theme choice**, the app's own or a theme pack's family, whose light or dark theme the mode picks. A choice with no theme for the mode shows the app's own there. One per user, not per board, and every window follows it at once.
_Avoid_: dark mode (a mode of macOS), theme setting

**Simplified design**:
The calmer, native-looking design being built beside today's, which is **Classic**: off by default, turned on in Settings › General › Design (marked Preview while it is built), and one per user, every window following it at once. It is a flag over the same components, not a second app: its own theme token values, and for the few components that must show something different, a different rendering. The theme picked in Appearance, a theme pack included, shows under it too, in its shapes and type with the pack's colours. See `docs/adr/0022-simplified-design.md`.
_Avoid_: Pro, simple mode, new UI, redesign

**Technical details**:
Under the **Simplified design**, the layer it hides by default: branches, models and harnesses, pull requests, raw states, terminals and drawing tools. One switch, Show technical details (in Settings › General › Design and in View › Show Technical Details), adds the layer back; it only adds, and moves nothing else. Off by default and one per user. Two things show with it off: the creation toolbar's drawing tools and new terminal, and the pull requests in an agent's **shelves**, so its open changes are never hidden. **Classic** always shows the layer and has no switch.
_Avoid_: advanced mode, developer mode, pro details

**Theme token**:
A named value for one role in the look, such as `--state-waiting` or `--space-2`, defined only in `tokens.css`. A theme overrides tokens; nothing else writes a literal colour, spacing, radius, font, shadow or motion value (`docs/theme-tokens.md`).
_Avoid_: variable, design token

### Sessions and agents

**Session**:
One long-running process owned by the daemon and attached to a PTY: an agent or a plain shell. Outlives its window and the app.
_Avoid_: terminal (a terminal is a view of a session), process

**Agent**:
A session running a harness (`claude` or `codex`), with an optional model (`opus`, `sonnet`, `haiku`, Codex's `gpt-5-codex`, `gpt-5`, or any id typed; the harness's default without) and **role**, in its own worktree (or, for an external session resumed in agent-board, in a folder of the user's that it doesn't own, which deleting it leaves alone). Its repo is the one it was started from (the repo picker's, else its zone's repo or default repo; for a resumed external session, its folder's repo, or the folder itself outside git, with no branch), and stays its own: its tile can sit in any zone or loose on the board, and then shows a repo chip when it is outside every zone of its repo. Deleting it, its pull requests and its linked issue all go by its own repo, never by the zone its tile sits in. One started with no task sits at its prompt, named `new-agent-N`.

**Reasoning effort**:
How hard an agent's model thinks before it answers: `low`, `medium`, `high`, `xhigh` (shown as Extra high) or `max`, or its harness's own without one. Claude Code takes every level (`--effort` at launch); Codex all but `max` (`model_reasoning_effort` at launch). Picked at spawn (New agent's Reasoning chip, `agent-board new --effort`, `new_agent`'s `effort`), else Settings › Agents › Reasoning gives it: its role's level (implementers, reviewers, designers), else the one for every new agent; a Codex agent given `max` there gets `xhigh`. A running agent's ⋯ › Reasoning changes it as the user would: a Claude agent has `/effort <level>` typed at its prompt between turns (at once if it is there with nothing typed, else once its turn ends: never into a turn, a question or the user's typing), and a Codex agent, which has no such command, takes it when it next starts, as an ended agent does; either way it is the one a restart starts it with. Its Default row goes back to the harness's own, which no harness can be told live: that too applies when the agent restarts. The menus say what the outer levels cost (Low is fastest and uses least of the plan, Max slowest and most). The tile (a badge, or the Simplified design's technical line), `show` and its shelves show it, and say "after this turn" or "on restart" until it takes. An orchestrator picks it at spawn, and changes a crew agent's later with `agent-board effort <ref> <level>` (the MCP `set_effort`): the same as the menu, scoped and logged as `interrupt` is; `send` types no harness command.
_Avoid_: thinking level, reasoning (alone, in code)

**Role**:
What an agent started as is for in a flow: **implementer**, **reviewer**, **follow-up reviewer** or **custom**, or none. A custom role may carry a **name** its orchestrator or the user makes up (`designer`, `release prep`: trimmed, at most 24 characters, no control, format or bidi characters; matched in ASCII case only), which its badge, `tree`, `show` and `whoami` show in place of "custom"; one with none shows "custom". Picked at spawn (New agent's role chip, whose Named role… takes a name, the repo picker's, or `agent-board new --role`, where a built-in role's name in any case is that role and any other name a custom role of that name), it starts the agent with its zone's **role template**, filled in, before its issue and task, and shows as a badge on its tile. Only the reviewer roles review a branch; a named role works on a branch of its own, as an implementer does. A reviewer or follow-up reviewer reviews a branch (in New agent, another agent's, picked under Reviews): it starts on a detached checkout of the branch's tip, in a worktree of its own, with no branch of its own to push (as a review loop's reviewers do; it could still push to a branch by name); its tile reads `detached @ <commit> · <branch>`. Not the same as a review round's **reviewer**, which the Review tab starts.
_Avoid_: persona, job

**Role template**:
A zone's prompt for one role, edited from its tab's ⋯ › Role templates… and kept by the daemon. Until edited it is its **seed**: the repo's worker prompt for the role (`impl-prompt.md`, `review-prompt.md` or `rereview-prompt.md` in its worker skill), else the app's own; a custom role's starts empty. A named role's is the zone's for that name (in any case; the dialog lists each name used in the zone or among the **default roles**), else the default role of that name, else empty: never a seed, so a named role with neither starts with its task alone. An orchestrator may write one, so a named role's template is checked as an orchestrator's prompt is (no leading `!` or `/command`, no control or format characters), when it is saved and again, filled in, when an agent starts with it. That holds for one the user saves in the dialog too: a zone's row doesn't say who wrote it, so the check at start can't tell them apart. A built-in role's template is the user's alone (no orchestrator writes or removes it) and isn't checked. Its `{{issue}}` (the issue's ID, or `none` with no issue: never the branch), `{{branch}}`, `{{worktree}}` and `{{prev_review}}` (and the worker prompts' `{{round}}`, `{{impl_worktree}}` and `{{prev_sha}}`) are filled in as plain text, never through a shell. An agent loose on the board uses its repo's zone's. An orchestrator that writes the whole prompt starts the agent with `agent-board new --no-template` (`template: false` in `new_agent`): its first message is then exactly the prompt (and the issue), and without the flag `new` and the tool's result say which template the message began with.
_Avoid_: prompt preset

**Default role**:
One of the app's own list of named roles, each a name and a template, used by any zone that saved no template of its own for the name. A session that may orchestrate (or the user from a shell or terminal) reads the list with `agent-board roles` or the MCP tool `roles`. Since the list reaches every zone, only an orchestrator of the whole board (or the user's side) changes it (`roles set|remove`, `set_role`, `remove_role`); a narrower one sets its own zone's template for a name with `--zone`. Each change is in the **activity log**. A built-in role has none: its template is each zone's.
_Avoid_: global template, role preset

**Agent tool** / **Shell tool**:
The toolbar's New agent (`A`) and Shell (`` ` ``): dragged off the toolbar onto the board, or armed with a click (or the key) and then a click on the board, they carry a ghost tile under the pointer, and the new tile lands where it is let go, in the zone under it or loose on the board. An agent dropped in a bound zone, or a group with a default repo, starts at once; anywhere else the repo picker opens on its tile.

**Harness**:
The agent CLI a session runs: `claude` or `codex`.
_Avoid_: provider, model, engine

**Shell session**:
A session running a plain shell with no harness. Each pane of a shell tile is one.

**Shell tile**:
A tile holding one or more shell sessions, laid out as panes in its window. It sits in a zone or loose on the board, like a sticky note, and dragging it in or out of a zone moves it into that zone or out onto the board. Made in a zone, its shells start in the zone's folder, or a group's default repo, else the home directory; made loose (the Shell tool), in the home directory. Its **folder chip** shows the folder its first live pane is in, following `cd` (`~` at home), and opens a new pane at home, in a recent folder or one browsed for. Moving it, binding or unbinding its zone, or a new pane elsewhere never moves its running shells. Its window has **tabs** as an agent's does, its own panes the first; its other tabs are never tiles. Closing its last pane removes it, unless it has other tabs, when the next becomes its first; the tile keeps its own folder, where its new tabs and panes start.

**Pane**:
One box of a session window, with its own strip of **tabs** and showing one of them: the window splits into panes side by side or one above the other (⌘D, ⇧⌘D, the strip's Split, or a tab dropped on a pane's edge), each new pane holding a new shell tab, and resized by dragging the divider between them. The pane with the keyboard is the focused one (its strip underlined, of several); ⌘⌥ and an arrow (Ctrl+Shift+Alt and an arrow off macOS) move the keyboard to the pane that way. A pane that loses its last tab closes. How a window's panes are laid out is kept with the daemon, per agent or shell tile, across restarts; a window that never kept one shows its tabs in one pane, its strip the window's own. A shell tile's own panes are split inside its tab, tmux-style: a shell session each, from the details' Split horizontally and Split vertically while its own tab shows (anywhere else they split the window, as ⌘D does) and its folder chip, each labelled in its header. A shell or agent's tab split inside itself before window panes is laid out as the window's panes as its window opens, each of its panes a tab of its own, where the tab was, no shell restarting.
_Avoid_: split (for the pane itself; a split is what divides two panes)

**Tab** (terminal tab):
One of the tabs in a **pane**'s strip of an agent's or a shell tile's session window: each shows one **surface**, the agent's own (a shell tile's own panes, named after the tile, in its window), one of its **shell tabs**, or another session shown there. A window starts with one pane, the agent's own tab first. **+** (⌘T) opens a shell tab in its pane where the agent started (in the tile's folder for a shell tile), at a folder browsed for, or running one of that folder's package scripts (named after it, such as `pnpm dev`), or shows another agent or shell tile there (**Show a session**), or a web page (**Web…**, a **web tab**); ⌘1–9 pick the focused pane's tabs (⌘9 the last), as ←/→ do in the strip. A tab drags along its strip, onto another pane's strip, or onto a pane's edge, splitting it there, in its window or in another of the app's, popped out too: a shell tab, a pull request, a web page or another session, but the window's own tab only within its window. Let go outside every window, a tab pops out where it was let go: a shell tab as a shell tile of its own (**Moving a shell**), another session as that session's own window, the window's own tab as its window, a pull request or web page into a **tab window**. Off macOS these are Ctrl+Shift+T, D, W and 1–9, Ctrl+Shift+Alt+D for ⇧⌘D: Ctrl's own keys (Ctrl+D ends input) stay the terminal's. The window-level tabs (Terminal, Review, Activity) are not these. A shell tab's shells are ordinary shell sessions its agent or shell tile owns: they keep running when the window closes, survive a restart (stopped by it, resumable), and end with the agent or tile when it is deleted. Closing a shell tab (its ×, shown on hover and on the tab showing, a middle-click, or ⌘W with it showing in the focused pane; Ctrl+Shift+W off macOS) ends its shells, asking first while one still runs, as deleting a shell tile does; closing a shell tile's own tab, which has a × while the tile has other tabs, ends its own panes, and its next tab becomes its own. Closing another session's tab only takes it out of the window. The agent's own tab has no close (⌘W there is left to the app), and an agent's own pane is ended only by Stop or Delete. A shell tile whose first tab loses its last pane keeps going while it has other tabs: the next becomes its first. A tab is never a tile on the board, but it can **move** to become one.
_Avoid_: window tab (Terminal, Review, Activity)

**Surface**:
What a **tab** shows: the window's own session (an agent's, or a shell tile's own panes), one of its shell tabs, or another agent's session or shell tile, shown there and still its own: it isn't moved, its identity doesn't change, it keeps running when its tab closes, and its tab goes when it does (deleted, or a tile becoming a tab). Seeing an agent's session there marks its ask seen, as its own window does. It is a second view of the same terminal: while its tab shows, the last window to resize it sets its size; a tab not showing never resizes it, nor marks its ask seen. A **PR tab** is one too, so is a **web tab**, and so is a **Gate tab**.
_Avoid_: view, panel

**Moving a shell**:
Dragging a shell tab by its tab, or a pane of a split by its header, onto another session window's tab strip or body, or onto an agent's or shell tile, makes it one of that window's tabs: where it was let go on a pane's strip or at a pane's edge, else after the focused pane's others; onto bare board, a shell tile of its own where it is dropped, named as the tab was. A pane dropped back on its own window becomes a tab of its own there, unless it is let go over itself, which gives the drag up. A shell tile dragged onto an agent's tile, its expanded tile or its session window becomes one of its tabs, its own tabs coming too (dropped on any other tile, it overlaps that one as before). The agent's own tab never moves, nor a shell tile's first while it has other tabs. Moving never restarts anything: the shell's processes, output and folder go with it, and only its owner, or its place, changes, so it speaks for its new owner on the board at once (its `AGENT_BOARD_ZONE_ID` stays the zone it started in, as for a moved tile). A shell kept in another agent's worktree shows an amber "runs in impl-auth's worktree" tag in its new window. The window it lands in keeps the tab it shows, the keyboard goes to the board, and ⌘Z takes the move back (a pane back into its split as it was laid out, a tab back into the window pane it left while that pane is still there), ⇧⌘Z does it again. Moving a tab between a window's own panes changes only its layout, and isn't undone. Connectors on a tile that becomes a tab are kept, unseen, and show again if it comes back. A moved shell keeps its name, so a window or zone may hold two of a name until one is renamed; nothing is renamed by a move, so an undo puts back exactly what was. A shell tile expanded when it becomes a tab comes back expanded on undo. A move into an agent or shell tile being deleted is refused. All of it works between OS windows too: from a pop-out onto the board's windows and tiles, the other way, and between two pop-outs, with the same slot and overlay; ⌘Z in a pop-out takes back the last move from any window (while the board's window is open). A shell tab or pane let go outside every window becomes a shell tile loose on the board beside the tile it left, and its window pops out there; a shell tile's own tab, alone, pops its window out as it is. A shell tile popped out whose only tab is dragged into another window closes, as it becomes that window's tab.
_Avoid_: adopt, transfer

**Shells chip**:
The chip in an agent tile's footer when it has shell tabs: "2 shells", one dot per shell (at most five, then "+N"), green running a command, grey idle, red when its last command failed (as bash and zsh report, through the shell integration the daemon adds) or the shell exited non-zero. Hovering it lists them, with the ports a running one listens on or the exit status, and "+ New shell in this worktree"; a row opens the session window on that shell's tab, over Review or Activity too. Deleting the agent says its running shells end with it. A shell never changes the agent's state or joins Needs you.

**Subagent**:
An agent spawned by another agent inside the same harness process (e.g. Claude's Agent tool). Has no PTY of its own; shown as a character on its parent's tile.

**Transcript**:
The file a harness writes its conversation to as it goes: Claude's JSONL under `~/.claude/projects`, Codex's rollout under `~/.codex/sessions`. Its format is the harness's own and changes without notice; agent-board only reads it.
_Avoid_: log, history

**Chat view**:
An agent's session window or expanded tile showing its conversation read from its transcript, instead of its terminal, picked with the Terminal / Chat switch at the right of the pane strip (the dark strip over the pane, beside its tabs). The choice is kept per session and is the same in its session window, pop-out and expanded tile, and outlasts a restart. It shows its messages (the agent's as Markdown, never loading anything), its thinking, tool calls, compactions and interruptions, its subagents' messages, the agent's **live state**, and a message box at its foot, in the **chat style** picked. A message sent from the box shows at once, saying whether it is sending, queued until the agent's turn ends, waiting for its session to start, not sent (with Retry), not delivered, or not seen in the transcript, until the transcript's copy takes its place; once the daemon has answered, it can be discarded. A block of pasted text in a message shows folded, as "Pasted text (N lines)". A transcript the chat can't read leaves the terminal only. The chat is the agent's own pane's: picked while a shell tab shows, it brings the agent's own tab forward, and its shell tabs stay terminals, with no message box under them.
_Avoid_: chat mode, TUI view

**Chat style**:
How every **chat view** draws an agent's calls and **live state**, one choice for the app, kept, picked in Settings › Agents › Chat or from the switch over a chat: **Cards** (the default; a card per call, thinking, compaction or interruption, opening on a click, the live state a card at the end), **Timeline** (a dot per event on a rail, coloured by state, a run of calls as stacked dots and one line, the live state at its foot), or **Status line** (finished calls as chips under the messages, the live state one line over the message box). Expand all and Collapse all open and close every card or run.

**Live state**:
What an agent is doing now, at the end of its **chat view**: from its hooks and its transcript, what it waits on you for first (a permission prompt, a question, a plan), then its usage limit, compacting, a failed turn, a call running or thinking; between turns, interrupted, or done and how long the turn took. What waits on you is answered there: Allow or Deny, an option or a reply, Open plan or Approve, Continue on credits.
_Avoid_: status (an agent's own status line, `agent-board status set`)

**Ephemeral agent**:
An agent that runs one task, leaves an artifact (e.g. a review doc) and terminates.

**Long-lived agent**:
An agent re-run by a schedule (a clock that messages it) or webhook trigger.

**Schedule**:
A cron trigger: a five-field cron expression in the daemon's local time (which follows the system's time zone), kept as a **clock** on the board. An agent's schedule is the clock that messages it (the soonest, if several do): its tile carries a clock badge with the next run, which selects the clock, and its ⋯ Schedule… opens the clock's editor, or makes a clock on its tile's left, joined to it. A schedule outlives its agent's session: a run relaunches an ended agent.

**Clock**:
A kind of board item that is a schedule: a tile-wide card with a small clock face on its rounded left end, the schedule in words ("Weekdays 09:00"), what it does and when it next runs, and a strip of squares for its last ten runs (green done or sent, red failed, grey skipped, accent still going); folded, a pill with the face, the words and how soon it runs. It either messages the agent it is joined to (a dashed tether leads to that agent's tile), or starts a **fresh agent** in its zone at each fire time, with its task, harness, model and role, waits for that agent's turn to end (a turn that ends asking you something leaves it open and `waiting` for you, its run going on until you answer), keeps its final message in the clock's **run history** (and, as the clock says, as an agent note where the tile was, or as a hand-off to another agent), and closes it unless told to keep it or it flagged you. What a clock does with its agent after each run is its mode: **hibernate** (it messages its agent, then pauses it until the next run wakes it in its conversation), **close** (a fresh agent each run) or **leave idle** (it messages its agent and leaves it at its prompt). A run that messages an agent goes on until the turn it started ends, that turn's final message its result. A run whose agent flags you (`needs_you`) says so in its history, and leaves its agent up for you: hibernate doesn't pause it and close doesn't close it. A quiet run never reaches Needs you. An agent may change its own clock, and no other (`agent-board schedule set|stop`, `clock_set`): its mode, or off, with a reason the clock shows until the user sets the mode again or turns it back on; and add one of its own (`schedule add --self`). A hibernating or leave-idle clock with no agent joined can start its own on its first run, then keep it. A clock can be saved as a **clock template**, by name, for any zone: its schedule, prompt and mode, never its agent; new clocks start from one (`schedule add --template`), and an agent replaces or removes only templates it saved (`schedule template save|list|remove`). An orchestrator's clock starts its agents in its crew, and none once it is gone; a clock starts none while three it started are still on the board. A clock that can't fire (no prompt, no agent joined, a fresh one in no zone) is **not set**. Made from the board's right-click menu (Add a clock), a tile's ⋯ Schedule…, or `agent-board schedule add` (`add_schedule`); double-click edits it. Deleting its agent leaves it unjoined.
_Avoid_: timer, cron job, alarm

**Agent state**:
One of: `running`, `thinking`, `waiting` (for input), `needs-permission`, `idle`, `rate-limited`, `failed`, `done`, `scheduled`, `stopped-by-restart`, `hibernated` (**paused**), `handing-off` (delivering along its edges, a **hand-off**), `starting` (started with a first prompt, before that prompt's turn begins, so it is never `idle`, and a message or scheduled run sent to it is queued until it is up, and handed back, never dropped, if it can't be typed, while a hand-off waits on its edge; a Claude agent started with no task, or relaunched with no new prompt, shows `idle` but queues the same way until its session is up; its tile is a **start**'s, labelled starting, with the last line its terminal shows, or Claude's **trust screen** row), `on-command` (**on a command**, below). `rate-limited` means its usage limit stopped its turn; it stays so, past Claude's idle prompt, until a turn starts (**Continue on credits**). `done` means the agent's session has ended, or the user stopped it; `failed` that it crashed or was killed otherwise, or that a turn failed. `scheduled` means a long-lived agent sits at its prompt waiting for its next run, not for you; it is never in the needs-you inbox. A scheduled agent whose last message asks you something is `waiting` instead. `stopped-by-restart` is the state an agent is **stopped by restart** in.

**Human status**:
The one of six an agent is read by, whatever its **agent state**: **Needs you**, **Problem**, **Working**, **Done**, **Paused** or **Scheduled** (`humanStatus`), with a few words of why ("Asks you", "Waits for impl", "Usage limit"). Whatever the needs-you inbox lists is Needs you: a permission prompt, a question, a plan, a flag, and every finished turn when **Needs you shows** lists them. Needs you also covers what the inbox doesn't list yet: an agent **stopped by restart**, a finished turn at its prompt whose last message ends in a question mark, and a pull request of its own still open, even once it has ended. A reviewer at its prompt asking none of that is Paused while the agent it reviews works or is paused. An ended agent is a Problem when the daemon says it failed, else Done, whatever its exit code. The Simplified design shows it as a **status mark**: a glyph, or with Settings › General › Design › Show each agent's status as › Characters the orange Claude character in a pose, always beside its word.
_Avoid_: state (that is the harness's own, in the daemon's words)

**Character**:
A small figure on an agent's tile that acts out what the agent is doing, beside its status word and never in place of it. Every agent shares one body colour, terracotta; its shape tells the harness apart: round for Claude, square for Codex. Picked once for both designs in Settings › General › Design › Characters: **Off**, **Bean & Block** (the default), **Pebble** or **Pixel**. It changes with one dip, never loops, and is drawn by the board from the agent's state.
_Avoid_: avatar, mascot

**Trust screen**:
What Claude shows before its session starts in a folder it has never opened: "Quick safety check … ❯ No, exit / Yes, I trust this folder". It fires no hook, so a starting agent's first prompt waits on it. The daemon reads it from the agent's screen and flags the user (never an orchestrator); the tile and Needs-you offer **Trust folder**, which answers it yes on the user's click, and the first prompt is typed once Claude is up. A repo or folder zone the user has opted in (**Trust this zone's folder for new agents**, off by default) has the daemon answer it the same way for agents in its folder and its worktrees, and their tiles' hover cards say "Trusted by its zone's setting". The board never types into it otherwise, as Enter there exits Claude, and never writes Claude's trust settings itself.
_Avoid_: trust dialog, trust prompt

**Start** (starting tile):
An agent being started, from the moment it is asked for (New agent, the repo picker, an issue, an orchestrator's `new_agent`) until its session's first hook. Its tile is on the board at once, before anything waits on git or the harness's path: dashed, with a spinner for its mark and its steps as they happen (reading the issue, creating the worktree, starting the harness), then, once its terminal exists, the last line the harness printed. It can be renamed and moved meanwhile, and its agent takes the name and place it has when its session runs (its branch keeps the name it was made with). It turns into a normal live tile when the session is up: its first hook, or output with no hook for a few seconds (a harness whose hooks don't reach the board), or a minute at most. A step that waits on another process (git, the tracker, finding the harness) fails after 3 minutes. A start that fails keeps its tile with the error, **Retry** and **Delete**: one that failed before its session ran has what it made undone (a harness already launched is stopped), and Retry starts it again from the beginning (asking first when the worktree brings Codex config of its own); one whose harness exited before its first hook is an ended agent, and Retry relaunches it in the same worktree with the first message it was started with. Removing a zone dismisses the starts in it. A start not yet an agent is kept in the daemon's memory only: after the daemon restarts, its tile says so, with Delete only.

**On a command**:
An agent at its prompt, asking you nothing, while a command it left running in the background still runs: a gate, a build, a dev server (`on-command`, `Agent.commands`). Its work goes on, so it neither looks finished nor waits for you: it is out of the needs-you inbox and its count (its idle prompt, firing meanwhile, leaves it idle), and a quiet "N running" count beside Needs you lists it instead. Its tile shows a teal "on a command" pill and the longest-running command with how long it has run (and "+N" for more). Claude Code's hooks name each command (a `Bash` call with `run_in_background`); whether it still runs comes only from the process table, a shell running it directly under the agent's harness process (never one under an MCP server), which is also how a Codex agent's are found. So an agent whose commands have all ended is idle or waiting again, whatever its status or last message says. A turn starting, or a question, takes over from it.

**Stopped by restart**:
A session whose process ended because the daemon went away under it (a crash, a shutdown, the machine restarting), not because it exited or the user stopped it. It shows its last output with a **Resume**: an agent's tile in its hover corner and ⋯ menu, under a dashed **stopped** look; a shell tile in a row of its own; a session window in a banner over the terminal. A banner counts them all, with **Resume all**: nothing starts again, and no tokens are spent, until the user picks. Resuming carries on an agent's conversation (`claude --resume`, `codex resume`), or starts a new shell in a pane's last folder under its old output, marked restored. An agent whose turn the restart cut off (it was running, thinking or on a permission prompt, not interrupted by the user) is then told "The app restarted; carry on from where you were." as its next message, until a turn begins; one that was idle, or had asked a question, is told nothing. A resumed agent's tile says nothing of the restart; one that had turns but whose conversation is gone says so, until a turn begins. An agent with a schedule is stopped by restart too, and resumed with the rest: its clock may not fire for days, if ever again. One still stopped when its clock fires is relaunched by that run.
_Avoid_: crashed, failed (those are the session's own doing)

**Paused** (hibernated):
An agent whose session the user or an orchestrator ended between turns to free what its harness held (its memory, mostly), keeping its tile, worktree, branch and conversation. Its state is `hibernated`. Only an agent at its prompt that waits on no one pauses: not mid-turn, not with a permission prompt, question or plan for you, not with a message never sent at its prompt or one being sent to it (a message sent while it is being paused waits, then wakes it); its pane keeps its last screen and drops into no shell. Its tile is solid slate over faint stripes, says who paused it and how long ago, and has a **paused** pill and **Wake** in its footer; Pause is in the tile's ⋯ menu (under Run) and the session window's Controls (greyed out with why when it can't), and `agent-board pause` / `wake` and the MCP tools of the same name are an orchestrator's. Wake, a message (the composer, `send`), a hand-off or a scheduled run starts it again in its conversation (`claude --resume`, `codex resume`), a message as its first. It stays paused across a restart. Its orchestrator hears it as `paused` (by whom), not `ended`. Closing a paused agent (Stop, `close`) leaves it a plain closed agent, without waking it. Nothing else pauses an agent by itself, and the app never suggests it: only a **clock** set to hibernate its agent pauses it, once each run's turn ends, unless that run flagged you.
_Avoid_: frozen, suspended (a stopped process keeps its memory; this frees it)

**Status**:
What an agent says it is doing now, set from its own session with `agent-board status set` or the board MCP's `set_status`: one line, at most 200 characters, and how far through it is (0-100) if it says. Its tile shows it in place of its task until it sets another; the last writer wins (ADR-0010). An orchestrator can set the line of an agent in its crew (`status set --agent`, `set_status` with `agent`; never one outside it), and the tile then marks the line with ◎, its hover card saying which orchestrator set it, until the agent sets its own. How far through it is shows as a hairline on the tile's bottom edge. The tile body is always this line, else the task, unless the agent asks something (a permission prompt, a question, a plan): an idle agent's last message is on a card that shows below its tile after about half a second of hovering, and in its session window's details.
_Avoid_: description (that is the task it was given). Its line of text is its **summary**.

**Purpose**:
What an agent says it is for, in a line of at most 80 characters: "Hooks go quiet outside work hours". It is set with `agent-board status set --description <text>` or `set_status`'s `description`, by the agent or its orchestrator for a crew member, and stays until it is set again, across restarts; an empty one clears it. Unlike its **status** it says what the agent is for, not what it is doing now. It is the sub line of the agent's ⌘K row (unless it needs you, when that row says what it asks), ⌘K finds the agent by it, and the tile's hover card leads with it. The tile itself does not show it. The flag and field are named `description`; in the code it is `Agent.purpose`, since an agent's description is its task.
_Avoid_: description (that is the task it was given), summary (the status line's text)

**Work category**:
Where an agent's work stands, for the overview: one of seven, ordered by who acts next, in four groups. **On you**: Needs help, Ready for review. **Stuck**: Blocked. **On others**: Waiting on others, In review. **On its own**: Working, Done (ADR-0024). The agent sets its own beside its status (`agent-board status set --category waiting-on-others --label "With Legal" --on "Northwind Pay support · #48213"`, `set_status` with `category`, `label`, `waiting_on`), or its orchestrator sets it for a crew member; `--category none` gives the board's guess back. A **label** of its own (at most 40 characters) shows in place of the category's name and keeps its group; who it waits on goes only with the two On others. It stays until another is set, across restarts, except Done (which `--done` and a hand-off also set), which goes with the agent's next prompt. Without one the board guesses from what it sees: its state, its pull requests and their checks, a reviewer agent running on its work. Needs help (anything the needs-you inbox holds for the user) and how an ended session ended win over what the agent set. The agent's **human status** says what it is doing at its prompt; its work category says what its work waits on.
_Avoid_: bucket, lane (an arrange's cluster per issue), shelf (the shelved layout's To do, Doing, Waiting, Done), column (the overview's column is a project)

**Overview**:
A window of its own, opened from Window › Overview (⌘⇧O), that shows every agent on the board at once: a **column** for each project (a zone, in board order, with agents in no zone last under "On the board") and in each column its agents grouped by work category, longest waiting first. A **thread** is one agent's card in it: its name, its category's chip, how long it has waited, its line (its status summary, else its last message) and, for the On others, who it waits on. A dashed edge marks the board's guess; a solid one, a category the agent set. It searches, filters by group and sorts (the columns stay in board order unless asked to put most on you first, so they don't move by themselves), and keeps when it was last looked at, so what changed since shows a dot. Orchestrators are left out, and reviewer agents too unless they need the user or are stuck.
_Avoid_: dashboard, morning view (it is live all day)

**Record** / **guessed**:
An entry an agent puts on its own **sidebar** (its session window's details) as it makes it (`Agent.records`, kept by the daemon): a pull request it opened (`agent-board record pr <url>`, `record_pr`; `open-pr` records its own), a **hand-off doc** it wrote (`record doc <path>`, `record_doc`, on its own sidebar or, with `--for orchestrator`, on the orchestrator's that started it), a **pin**, and each agent it starts (recorded by the daemon). Records win; what the board **guesses** from gh, hooks and its worktree's `.agent-board/handover.md` fills the gaps, in every section. A recorded row has a solid green rule and a × that deletes it with Undo; a guessed one a dotted rule and an italic "guessed" tag. The user can delete a record but not edit one: a deleted record hides its guess too ("1 hidden · Show") until the agent records it again.
_Avoid_: inferred (say guessed), entry alone

**Hand-off doc**:
A file an agent wrote for someone to read (a handover, findings, a review, a plan), recorded on its sidebar, or its orchestrator's, and opened read-only in a **Doc** tab of that agent's session window. A hand-off with a handover file records that file on the agent too.

**Pin**:
A **record** an agent puts on its **sidebar** for the user to see, in a Pinned block of its **page** (the Full sidebar's Pins) (`agent-board pin`, `pin`): a file (a Markdown or HTML one opens in a **Doc** tab, any other is shown in its folder), a link a web tab opens, or a short note under a label, shown on the sidebar itself. Pinning the same file, link or note label again replaces it; `unpin` takes it off, gone with no Undo. Like a hand-off doc, it goes on the agent's own sidebar or, with `--for orchestrator`, on the orchestrator's alone, beside (never replacing) the orchestrator's own pins and its other crew's. The user deletes a pin as any record, with Undo, and never edits one.
_Avoid_: bookmark, attachment

**Page** / **block**:
What an agent writes for the shelf its **sidebar** opens on (`Agent.page`; `agent-board page`, `set_page`): the tab's name (at most 12 characters) and icon, and the **blocks** it is made of, top to bottom. A block is a heading (with its progress), key figures, a checklist (each line to do, doing or done, at most one doing), a callout, links (a web page or a file) or a note, and may have a title, an icon and a **tone**. Writing the page again replaces it whole; clearing it takes it off, and until there is one the shelf shows the board's Now. An agent writes only its own page, from its session (the shells of its own window, which carry its token, count as its session); no other agent or orchestrator reaches it, the sidebar has no control to edit or delete it, and it is no **record**.
_Avoid_: dashboard, widget, panel (say page and block); raw HTML (a page is blocks, never markup)

**Page icon** / **tone**:
The icons an agent picks for its page's tab, a block or a figure come from a curated set of about 40 of lucide's (`PAGE_ICONS`), which leaves out the board's own marks (a pull request, a branch, the crew, the workspace, pins, the robot, a flag, timers, Ask Claude's sparkles, the shelves' stack, and the faces of a link's, a note's or a file's row). A tone is neutral, blue, green, violet or teal (`PAGE_TONES`): never orange, which means Needs you, nor red, which means failing.

**Documents** (sidebar section):
Every **document** an agent showed (`show_doc`), with or without a card on the board, and its latest plan, listed on its **sidebar** in the order shown, each opening its Document or Plan tab. Not records: the agent doesn't write them, and the user doesn't delete them there. Hand-off docs stay a section of their own.

**Finished**:
An agent that says its work is done (`Agent.workFinishedAt`): it handed off (`agent-board handoff`, even with no edge out of it), or set its status with `--done` (`set_status` `done`). Not a turn ending, which an agent may do many times while a gate runs in its background, nor an **agent state**: it sits beside one, until the agent's next prompt clears it. Its tile shows a **Finished** badge; `agent-board wait --until finished` waits for it, and its crew's orchestrator hears it once as a **crew event**.
_Avoid_: done (that is the state of an ended session), complete

**Board CLI** / **board MCP**:
`agent-board`, the command line every session the app starts finds on its PATH, which reads the board (`identify`, `tree`, `show <ref>`…), sets the caller's status and records entries on its sidebar; and the **board MCP**, the same as a few MCP tools agents get, whose instructions say only to read `agent-board --help`: the daemon serves it to Claude agents over HTTP, and `agent-board mcp` over stdio to Codex agents and any other client (ADR-0010). For an orchestrator, both also start, message, watch and close agents (ADR-0011), and lay out its zone: move tiles, **arrange** its crew, make groups and notes.
_Avoid_: API, control API

**Ref**:
How the board CLI names a thing: `<kind>:<start of its id>` (`zone:4f2a`, `agent:9c1e`), a unique name, or `me`.

**Board token**:
A session's own token, in its env as `AGENT_BOARD_IDENTITY`, which tells the daemon which session a CLI or MCP call comes from. Unlike the hook token it can't post hook events, so the model may see it.

**Orchestrator**:
An agent the user lets start, message, watch and close other agents through the board CLI and MCP (`agent-board new|send|wait|read|interrupt|restart|close`), join them with **edges** (`agent-board edge add|remove`), and lay out its zone (`agent-board move|arrange|zone|note`), inside its **orchestrator scope**. Only the user lets one: by a zone's setting, **Let agents orchestrate** (on by default), for every live agent in it, or for one agent by hand. An agent an orchestrator starts is one by its zone too, up to three deep: the user's agent, its agents, and theirs (ADR-0011). From a shell on the board, or a terminal outside it, the same commands act for the user (the **user's side**), on any agent.
_Avoid_: master (that is the **Captain**), lead (fine in prose, not as the term)

**Captain**:
The one agent per board the user asks for work: an orchestrator at `board` scope, started only by the user from its panel's **Start the Captain**, in a folder of its own with no repo or branch (ADR-0019). It routes a request to the right zone's orchestrator (with `send`, or by starting one there with the orchestrator role), watches the zones' orchestrators, and keeps a digest of what needs the user in an agent note beside its tile. Its tile sits loose on the board with a teal CAPTAIN badge and dashed teal rails to the orchestrators it watches; ⌘⇧M or the Captain button beside the Needs-you pill opens its docked panel: Watching, For you (the Needs-you rows and its digest) and its chat. One session, two views: closing the panel stops nothing. A Captain a restart stopped, or that was paused, shows **Resume the Captain** (or **Wake the Captain**) at the top of the chat in its panel; one that exited shows **Restart the Captain**. It never answers a permission prompt, approves, merges or changes a setting, and the app never sends it anything of its own. The questions and plans of the orchestrators it starts wait for the user, as a top-level agent's do, never for it; and it starts no orchestrator in a zone whose **Let agents orchestrate** is off, telling the user instead.
_Avoid_: master, board master (its old name), router, supervisor, master orchestrator
_In code_: `master`, the Captain's old name. It is kept in the `agents.master` column and the `master.*` RPC methods (`master.start`), which renaming would break, and in file and folder names (`packages/daemon/src/master.ts`, `renderer/src/master/`). Say Captain everywhere else.

**Usage reading**:
The plan's 5-hour and weekly usage: each window's used percentage, what is left and when it resets, and when it was read. Claude Code passes it to a status line, so the status line agent-board gives each Claude agent posts it to the daemon, then runs the user's own (an agent whose project sets a status line gets none of ours, so Claude's trust still gates the repo's command); nothing is asked of anyone and no tokens are spent. The daemon keeps the newest, across restarts; one older than 15 minutes, or with a window that has reset since, is **stale**. A pill beside the creation toolbar shows it once there is one (hatched when stale); `agent-board usage` and the MCP `usage` tool read it. One reading for the board: it names no account, and Codex passes none.
_Avoid_: quota, budget (for the reading), rate limit (that is the state a limit puts an agent in)

**User's side**:
Who a board token's session acts for (`BoardCaller.side`): every session the app starts but an agent's own, that is a shell tile, a tab (an agent's too) and an ended agent's fallback shell, and whatever the user runs in it by hand; and a terminal with no token. It runs the orchestrator commands for the user, on any agent, and turns an agent's orchestrating on and off, but never types into a session, answers a permission prompt or changes a setting. An agent's own session is never on it, ended or not (ADR-0010, ADR-0011).
_Avoid_: shell caller, user caller

**Orchestrator scope**:
Which agents an orchestrator may act on: those in its zone (the default), of its repo, or on the whole board; and always the agents it started. Starting agents is no scope's: zones are only logical groups, so it starts one in any zone, in any repo, and that agent is then its own wherever it is. Any agent may also send back to an agent that messaged it, for an hour after its message, and do nothing else to it its scope doesn't allow (a **reply path**, one way: the answer opens none back). It lays out the tiles and notes in its scope and in the groups it made, and itself (at `zone` scope, only within its zone); loose on the board only at board scope; never grows a zone over another; and never moves an agent into a zone that would let it orchestrate.
_Avoid_: scope alone (that is a tracker's)

**Spawned by** / **started by**:
The orchestrator that started an agent (`spawnedBy`); none for an agent the user started. Once that orchestrator is removed its crew is **orphaned from** it (`orphanedFrom`), still apart from the user's agents, until another orchestrator takes it over (`orchestrate handover`).

**Crew**:
The agents an orchestrator started, drawn in a dashed frame (or, by a board setting, each with a "from" chip): every one of them in its zone, wherever an arrange or the user put it, round each as it is drawn (expanded, or pushed aside by an expanded tile). The frame holds no other tile, its orchestrator's included: a crew with other tiles among it (another's crew, the user's own agents, a shell), or with more than a free grid column or row between its tiles, is framed in parts, labelled once, on its first. An expanded tile pushes each part aside as one. One in another zone, or loose on the board, carries its chip instead, and so does a crew in a zone on **status shelves**. The crew beside its orchestrator, in its crew's columns, moves with it when it is dragged or lands in another zone; the rest stays where it is, and one that lands in the way of something keeps to its row. A crew goes at most three deep (`crew_depth`, fixed as each agent starts). A crew started from a **crew prefab** is the agents started from it, whoever started it: the user, with no orchestrator, or an orchestrator, as its own crew. A crew changes hands with a **handover** (`agent-board orchestrate handover <from> <to>`): the new orchestrator's from then on, with what the old one made.
_Avoid_: children, workers (fine in prose)

**Crew prefab**:
A saved crew shape: its members (each a role, harness, model and reasoning effort, and for a named role a template of its own), when each starts (on the prompt, at the builder's first hand-off, or by the lead), and a round limit (3 by default, 1 to 10). It never holds a prompt, issue, repo, branch, approval, edge, key or token. One library for the whole app, every board's: the built-ins (Solo agent, Implementer + reviewer, Implementer + code + design reviewers, Spike + reviewer, Lead and crew), then those added, each by its name in any case; only the user or an orchestrator of the whole board adds or removes one, in the **activity log**. Shared as a `.crew.json` file (`agent-board prefab export|import`), read strictly: a field it doesn't know is refused, and an import shows it whole before `--add` adds it. `agent-board new --prefab <name> -- <prompt>` (`new_agent` with `prefab`) starts the member that starts on the prompt, its builder or its lead (an orchestrator-role member, whose first message lists the crew it may start and the round limit); the lead and its crew are two levels of crew depth. "Lead" is the built-in Lead and crew's own word, as in prose: its member's role is `orchestrator`.
_Avoid_: template (that is a **role template**), team preset

**Running crew**:
A crew started from a **crew prefab** with reviewers at its builder's hand-off, whose loop the board runs, with rounds of its own, not the Review tab's **review rounds**: at each hand-off it starts that round's reviewers, fresh, on the builder's branch; once each has left its review it stops, ready to merge (every one approves, no blocker open), or hands the reviews back to the builder as the reviewers' own hand-off, up to the round limit, where it stops and offers one more round (`agent-board crew round`). It waits while one of its agents needs you, and closes its agents once the builder's pull request is merged. `agent-board crew` lists them, by `crew:<id>`; `wait crew:<id>` waits until one stops.
_Avoid_: pipeline, loop (fine in prose)

**Crew card**:
A kind of board item: a **running crew**'s one card on the board, put beside its builder as the crew starts. The board writes it from the crew's own record (its title from the first line of its prompt, its members as the prefab named them, its round, phase and stop), so it says only what the crew did, whatever a client sends: only where it sits, its size and whether its members show as tiles are the user's. A running crew keeps its card; once the crew has stopped the card is the user's to take off, and one more round puts it back. Its scope is where it sits, as a **steps card**'s is, and its own crew's agents read it wherever it is. It shows what the crew was asked, its rounds, a row for each member, and then its last hand-off while it runs, what it waits on the user for while it is paused (needs you), or where it stopped: ready to merge, round limit, merged, stopped, builder gone. Where it waits on the user it keeps the builder's pull request with its checks beside its buttons, and a round whose reviewers could not start says why. A row reads its agent as the window's design does: by its **human status** under Simplified, by its **agent state** under Classic. Its buttons are the user's own steps (open the pull request or an agent, one more round, take over, stop the crew); it approves and merges nothing. Taking a running crew's card off the board asks to stop its crew first, and the card stays until the user answers.
_Avoid_: crew tile, crew object

**Crew event**:
What happened to an agent, said once however often its state flips, which its orchestrator hears through `agent-board watch` or the MCP `wait` with `since` (`orchestrator.wait`): its turn ended, it **finished** (in place of that turn's end), it needs the user (a permission prompt, a question or a plan), it **flagged** its orchestrator (`flagged`, with the reason), its turn failed, it was rate-limited, its session ended (closed, exited, or removed), or a pull request was opened from its branch. Claude's idle prompt, moving it from `idle` to `waiting` a minute after a turn, is none, and a wait still takes it as `idle`; Claude's own question is `needs-you`. The daemon keeps the latest thousand, in memory, each with its **cursor** (`<run>.<n>`) to watch on from: one from before the daemon restarted gets everything since, marked missed.
_Avoid_: notification (that is the OS's), state change

**Activity log**:
The orchestrators' append-only log: who did or tried what to whom, and when, done or refused (`orchestrator.activity`): the agents they start, message, interrupt, restart, close and remove, the edges they add and remove, the tiles they move, the zones they arrange, the groups and notes they make, change and remove, the **default roles** they set and remove, and every agent's explicit **hand-offs**.
_Avoid_: audit log (fine in prose)

**Needs-you inbox**:
What agents ask of the user, oldest first, each row tagged with its kind: a permission prompt (any agent's, a crew member's too), and an orchestrator's or a top-level agent's **question**, **plan** or **flag** (a crew member's go to its orchestrator while that one is live). An orchestrator's **remove ask** is a row too. A **steps card** an agent waits on is a row too: **Steps**, a set it made of questions the user answers, until they are sent; **To-do**, a to-do of the user's it waits on, until it is ticked. A list the user made never is. Answerable without opening their shell; a flag has nothing to answer, only Open. A turn ending is none of these: only with Settings › Alerts › Notifications › **Needs you shows** set to explicit requests and finished turns does every agent `waiting` at its prompt count too. The pill, the dock badge and **notifications** follow the same list. Under the Simplified design the list is in sections: Continues the work (permission prompts, plans and to-dos), Reaching out to you (questions, steps to answer, flags and finished turns), then two that aren't requests and so count toward nothing: Ready for you to accept (an agent's open pull request, with **Accept changes**, which merges it 10 seconds later unless undone) and Problems (an agent that failed, until it is opened; one **stopped by restart**, or one at its usage limit, while it stays so).

**Remove ask**:
An orchestrator asking the user to remove tiles it didn't start, in its scope. One row in the **needs-you inbox** lists them all, with one Deny and one Allow for the whole batch. A tile still running, with a live agent it started, or with a reviewer the ask leaves out or holds back, is listed apart and goes only if the user ticks it. Allow removes each one as the user's own Delete does, never forced, and keeps a tile whose reviewer stays; Deny, a timeout, or the ask being withdrawn (the orchestrator's call ending, or its next turn beginning) removes nothing. The orchestrator is told what went and what stayed. Nothing answers it but the user.
_Avoid_: remove request, delete prompt

**Flag** (needs you):
An agent's "please look" (`agent-board needs-you <reason>`, the MCP `needs_you`): blocked, its work ready for review, or a decision needed. No question, and nothing waits: its turn goes on. One per agent, its reason a line, replaced by the next; kept in memory, gone when its session ends. It reaches the user in the needs-you inbox, its tile showing the reason in orange, until they open its session or the agent clears it (`--clear`). A **crew** member's reaches its **orchestrator** instead, while that one is live, as do its questions and plans (but for the **Captain**'s crew, whose questions and plans wait for the user): typed at its prompt once it is ready for its next message, as a hand-off is (waking an orchestrator at its prompt at once, between check-ins too, a burst of flags as one message), heard as a `flagged` **crew event**, shown in violet on both tiles (the orchestrator's as a count of open crew flags), and cleared when the orchestrator sends it a message. An orchestrator that can't settle it passes it on to the user with `--via`, which names the crew member on the inbox row.
_Avoid_: ping, alert

**Question** (ask):
What an agent asks the user through the board MCP's `ask` tool: a question with up to nine options and, if it lets the user reply in their own words (always with no options), a reply field. Its call waits, and the agent is `waiting`, its pill reading "asks you" and its note the question and options, until the user clicks an option, sends a reply or **skips** it in the needs-you inbox, the wait times out (30 minutes by default), or the agent stops waiting (the harness cancels the call, its turn ends, its session goes). Only the user's click answers it: a timeout or a skip tells the agent there was no answer. An ask may hold up to four questions, answered one at a time and sent together; more, or a to-do, is a **steps card**. Put on the board, it becomes a steps card its call still waits on, whose Send answers it; one that ends half-answered is kept as a steps card too. One at a time per agent, held only while it waits (ADR-0014). A **crew** member's goes to its live orchestrator as its **flag** instead, and nothing waits (ADR-0016). Asked with `on_board`, it is put on the board at once, as a steps card. Unless put on the board, it opens from the **ask chip** on its tile.
_Avoid_: prompt (that is a permission prompt), request

**Steps card**:
A kind of board item: an ordered list of **steps**, each a question (pick one, pick any, yes or no, put in order, or in the answerer's own words) or a to-do (a tick, done by whoever it names), in sections from `## headings`. An agent puts one up with `agent-board steps new` (`steps_new`), or the user makes one. Nothing waits on it: the user answers its questions in any order and presses Send, and the answers are typed at its maker's prompt, led by `[agent-board]` (ADR-0014); a **crew** member's set is its orchestrator's to answer. Its scope is where it sits: in a zone, that zone's agents' (and orchestrators whose scope reaches it); loose, every agent's. It is saved with the board and stays until the user takes it off, after its maker ends too. An ask of up to four questions stays a **question**, unless it is put on the board.
_Avoid_: wizard, checklist (for the object), form

**Step** (on a steps card):
One row of a **steps card**: a question or a to-do, written as one line in the steps line format (`- [ ] text @who -> link`, `? text [a | b]`, `[any: …]`, `[yes/no]`, `[order: …]`, `(required)`). Always "step on a steps card" where a gate's step or a first-run step could be meant.
_Avoid_: item (board items are objects), task

**To-do list**:
A kind of board item: a checklist of things for the user to do (send a pull request for approval, restart the app), that only reminds: nothing on it is done for the user, and nothing ticks itself. An agent adds a line with `agent-board remind "<text>"` (the MCP `remind`); its first makes the agent's one list, under its tile and tied to it by a dashed **tether**, as an agent note is. The user makes their own from the board's menus. The user ticks, edits, adds, reorders and deletes its lines in place; a tick is saved with who made it and when, and is typed at no agent (an agent that wants to know reads its list with `remind ls --mine`). An agent ticks, unticks or takes off only a line it wrote on its own list. It folds to a pill of how many are left, and the zone's tab counts the lines left in its lists, in teal: a to-do holds no agent up, so it is never needs-you. A click on that count lists the zone's lists, by whose they are, to tick there; an agent's list is also the **To do** tab of its window.
_Avoid_: reminder (for the object), task, checklist card

**To-do** (on a to-do list):
One line of a **to-do list**: its text, who wrote it (the user, or an agent by name) and when, and once ticked who ticked it and when. Not a steps card's to-do step, which an agent may wait on (the **To-do** row in Needs you) and whose tick is sent to it: a to-do on a to-do list waits on no one, and is sent nowhere. Where both could be meant, say "a to-do on a to-do list" or "a to-do step".
_Avoid_: item, step

**List card**:
How the board draws a memory or a queue: a raised card of rows in the theme's neutrals, led by its glyph on a round face with its count, that folds to that icon alone and opens a peek of every row beside it. Zoomed far out, the folded icon stops shrinking, so it still reads.
_Avoid_: store

**Memory**:
A kind of board item: shared context that agents read and write with `agent-board memory` (`memory_read`, `memory_update`) and people on the board. It holds **entries**. Its scope is a steps card's, where it sits: in a zone, that zone's agents' (and orchestrators whose scope reaches it); loose, every agent's, and every agent writes to it. Set to **No agents**, only the user reads it, as a deleted zone's memory turns. Anyone in scope changes any entry, the user's too, and its history takes a change back. On the board it is a raised card in the theme's neutrals, led by a brain on a round face with its count: its name, who may use it (`Zone · api`, `Board` or `No agents`), its newest entries (pinned first) with who wrote each and when, and a box to remember something (`key: value`, or plain text). Folded, it is the brain icon alone, with its name under it. Either opens its peek beside it: every entry, to search, edit, pin or remove (with Undo). A row an agent just wrote flashes once. Made from the board's right-click menu (Add a memory) or `M`, named after its zone, or by `agent-board memory new`.
_Avoid_: notes (for the object), knowledge base, store

**Entry** (in a memory):
One row of a **memory**: a **fact** (a value under a key, which setting the key again replaces, or a keyless note) or a **document** (text kept whole under its title, up to 1 MB, from `--doc` or a file). An agent's read lists the facts in full and the documents by title and size alone; a document is read whole when named. Pinned ones are listed first; one untouched for 30 days reads as **stale** until someone edits it or says it is still true (`memory confirm`). The board counts the agents who read each entry whole, and who last did. Every change is kept as a version (`memory history`), and `memory restore` puts one back.
_Avoid_: record

**Queue**:
A kind of board item: **jobs** in order, each of a kind, for agents to take one at a time (`agent-board queue`, `queue_read`, `queue_update`), or, with the user as its audience, things for the user to go through, which no agent takes. Its scope is a memory's. What goes in and out is for the agents in scope and the user to decide; nothing in it is typed at any agent. A job its taker drops, or whose taker's session ends mid-job, goes back to the front, each drop counted. On the board it is a list card, as a memory is, led by a ticket (an inbox, for the user's) on a round face with its count of open rows: its name, who may use it, a line of counts, the taken jobs and then the rest in order (the next one to be taken marked), and a box to add a job or, with its switch, a note (a line each; a link after `->`). Folded, it is the ticket icon alone, a NEXT tab above it while a job waits and the next job under its name. Either opens its peek: every row, to search, edit, reorder, finish, put back (a taken one) or remove (with Undo). Made from the board's right-click menu (Add a queue) or `Q`, for agents and named after its zone ("api jobs"); an empty one, or its toolbar, makes it the user's ("To look at"). Or by `agent-board queue new`. A job an agent holds rides on its tile as a **ticket**, which shows its queue. The user **hands on** a waiting job by dragging its row onto an idle agent's tile, or with its row's Hand button: they pick the agent and write the message, and only that is typed at its prompt, as their message; the job is taken for that agent. A queue's **drain** (Start agents to take jobs, which its foot offers when no one is taking its jobs) has the board start a fresh agent for each waiting job, as a clock does, while fewer than its most (1 to 3) are taken; the user turns it on, or an orchestrator for a queue it made (`queue drain`). The user's own queue shows the **Needs-you** rows of its zone's agents (every agent's, loose) above its items, read live and never copied in, and what kind each item is (a pull request, a doc); **Start ▸** on it, or its row in the Captain's For you, goes through them one at a time in the **focus view** (↵ opens, → next, S skip, D done).
_Avoid_: backlog (for the object: backlog is a kind of row on the user's), inbox (that is Needs you), task list

**Job** (on a queue):
One row of a **queue**: a headline (the first line; a body after it may follow), its kind, and its state: queued, taken by an agent (a lease its session holds until it is done or dropped), or done. Its kinds go by who the queue is for. An agents' queue holds a **task** (the default), a **request** or a **prompt**, which agents take, and **info**, which is read and never taken. The user's holds **backlog** (the default), a **review**, **questions** and a thing to **read**, all the user's to finish. A queue that changes hands takes its rows with it as the nearest kinds of the other: task and backlog swap, info and read swap, a review or questions becomes a request, and a request or prompt becomes backlog. Done, a job keeps its finisher's **result**: what was done, in a line or a few. On the user's queue only, the user puts an open row off **later** (hidden until a time, or until shown again) or **skips** it (behind the next row that is shown); neither is a version in its history. A dropped job always goes back to the front, its drops counted: dropped by its taker, as the taker's session ends mid-job (not for a restart, nor a pause), or as the taker is deleted. "Job" and "note" still work as kinds when adding: a job is the queue's default, and a note is info (a thing to read on the user's).
_Avoid_: task, ticket (that is an issue)

**Ask chip**:
The chip on an asking agent's tile: a speech bubble in the waiting orange, how many questions it asks, and a dot for each, filled once answered. A click on it opens the **question** beside the tile, at full size whatever the zoom, one question at a time with keys 1–9, then the answers as chips above Send. Only a click opens it, never the question arriving. Esc or a click elsewhere closes it and keeps the answers so far. Its ⋯ has Put on the board, which makes it a **steps card** the agent still waits on. It replaces the question card that was drawn beside the tile.
_Avoid_: question card, ask card, popup

**Plan** (plan version):
What an agent shows the user through the board MCP's `show_doc` with `plan` (or `present_plan`, kept for agents that call it) before it carries the work out: a **document** with a decision, a title and a body, Markdown or HTML, inline or from a `.md` or `.html` file. Each one is the agent's next **version** (v1, v2…), kept in its history with its **decision**: Approve, Request changes (with comments) or Reject, by the user; or none, as it timed out (60 minutes by default) or was withdrawn because the agent stopped waiting. The user may edit a Markdown plan the agent waits on before deciding: their edit is a version of its own, by them, which the decision then applies to (**Approve with my edits**), and the agent is told the diff with the decision; an approved edit is written to the plan's file when it is in the agent's worktree. With `on_board`, the plan is a **plan card** on the board too. While one waits, the agent is `waiting`, its pill reads "plan to review", and its tile has a `plan v1` badge that opens the **Plan tab**. An HTML plan is untrusted: it is drawn in a locked-down view of its own (ADR-0014). A **crew** member's goes to its live orchestrator as its **flag** instead, written to `.agent-board/plan-for-review.md` (or `.html`) in its worktree, and nothing waits (ADR-0016). From a shell, `agent-board doc <path> --plan` presents it too but returns at once: the user's decision is typed at the agent's prompt later, as a document edit is (ADR-0014).

**Plan tab**:
A **surface** showing an agent's **plans**, as the Review tab shows rounds: a rail of its versions, each stamped with its decision; the one picked, Markdown rendered as the PR tab renders it, or HTML in a view of its own, served from memory, offline, going nowhere and opening nothing; and under the latest, while the agent waits on it, a comments field with Reject, Request changes and Approve. A waiting Markdown plan has a Read / Edit switch, as a **Document tab** has: saving an edit makes the user's version, and Approve becomes **Approve with my edits**. It opens from the tile's plan badge and the inbox's Show plan, in the focused pane, drags and pops out like a Gate tab, and closing it keeps the plans.

**Document**:
A longer Markdown (`.md`) or HTML (`.html`) file an agent shows the user, nicer to read than its terminal: through the board MCP's `show_doc` or `agent-board doc <path>`, as a **Document tab** in its window and, if it asks (`on_board`, `--board`), a **document card** beside its tile too. Nothing waits. The file is the document: it is read each time it is shown, and the daemon looks at it every 1.5 s, so the agent writing it again is its next version (v1, v2…), shown at once. Showing the same file again shows the same document. The user may edit a Markdown document inside the agent's worktree: their edit is **written to the file** (never through a link, nor to a file deleted meanwhile), and the agent is told what changed (`[agent-board] The user edited <path> (v2)` and the lines changed), typed at its prompt once it is ready for its next message, as a crew flag is. An HTML document is view-only, drawn as an HTML plan is (ADR-0014), and the user's comments on it reach the agent the same way. A **plan** is a document with a decision: `show_doc` with `plan` presents one from a file and waits, as `present_plan` does. A document goes with its agent.
_Avoid_: doc (that is a **hand-off doc**), page, artifact, attachment

**Document tab**:
A **surface** showing one **document**, named by its file. **Read** renders it (Markdown as the PR tab renders a description; HTML in a view of its own). For Markdown, **Edit** splits it into its source on the left and the live render on the right; ⌘S saves (writes the file and tells the agent), esc leaves Edit with nothing written, the first esc taken by the editor before the board's. While the user edits, the tab stops following the file: a rewrite by the agent meanwhile is a banner offering **Take theirs** or **Keep mine**, the only way to write the user's over it (Save is disabled meanwhile, and ⌘S moves to Keep mine); the agent is told its changes were undone. It opens in the agent's window as the agent shows the document (shown as the window next opens), from the tile's docs chip, and from a document card; it drags and pops out like a Plan tab, and closing it keeps the document.

**Document card**:
A kind of board item an agent's `show_doc` with `on_board` makes beside its tile: a white page with a folded corner, a type tag (MD, HTML), its title and first lines fading out, and its agent and version at its foot, tied to the agent's tile by a dashed **tether** as an agent note is. Its toolbar collapses it to a slim bar (type, title, author) to keep a busy crew tidy, and takes it off the board, which leaves the document a tab of its agent. Double-click or **Open ↗** opens its **Document tab**. It says **you edited** until the agent writes the file again. It is saved with the board, so it survives a restart, and goes with its agent.
_Avoid_: doc note, file card

**Plan card**:
A kind of board item an agent's plan shown with `on_board` makes beside its tile: a page with a PLAN tag, its file's name, its title and version, and a stamp of how it stands, tied to the agent's tile by a dashed **tether**. One for each agent, showing its latest **plan**: a new version updates it in place. While the agent waits, **Review plan** opens the inbox's decision beside it; once decided, it keeps the stamp (approved, changes asked, rejected) until taken off the board. The plan is read and edited in its **Plan tab**, never on the card. It is saved with the board and goes with its agent.
_Avoid_: plan note, decision card

**Onboarding**:
The first-run flow: Welcome, Connect your tools (each CLI, GitHub, Linear, global hooks and notifications, checked and fixed in place), a quick tour of the board, and Finish (a first zone or the **sample board**). It opens by itself only on an empty board that has never been through it, can be skipped at any step, and Help › Getting started reopens it. Under the Simplified design it is two steps: the **Captain** says hello, then gets Claude ready (Claude Code installed, and signed in), with no tour or Finish.
_Avoid_: wizard, setup (for the whole flow)

**Sample board**:
A board of made-up agents in every state that onboarding can show. Drawn by the app alone: nothing behind it runs or is saved, and no tokens are spent.
_Avoid_: demo mode

**Notification**:
The OS notification the app raises once for each new request in the **needs-you inbox**: a permission prompt, a **question**, a **remove ask** (how many tiles, the first few by name), a **plan** or a **flag** (with its reason), and, with finished turns listed, a turn that ended waiting. A turn ending, a failure or an end raise none. Clicking it opens the agent. Settings › Alerts › Notifications turns them off, and on whether they come while the app is in front (off by default: only the pill changes then). A **muted** agent raises none but still shows in the needs-you inbox, whose size is on the dock badge. Under the Simplified design it is drawn as macOS draws a banner: the agent's name, what kind of request it is (Question, Permission, Plan to review, Needs you, Finished) and then the request; a question lists its answers under Options, and picking one answers it. A banner never allows: a permission or a remove ask offers no answer, only a click to open the agent. Settings › Alerts has one **Notify me when** pop-up (Something needs me, or Something needs me or finishes) in place of the three rows, and leaves turning notifications off and quiet hours to macOS (System Settings, Focus).

**Permission prompt**:
A tool call, by an agent or one of its subagents, waiting for the user's allow or deny. An agent can have several at once, and is `needs-permission` while any is pending.
_Avoid_: approval (that is a condition's command approval, ADR-0009), permission request (that is the harness's hook event)

**Question-tool prompt**:
Claude's question tool call (`AskUserQuestion`), which reaches the board as a `PermissionRequest` like a permission prompt but is listed as its questions, each with its options and an "Other" answer. It can't be allowed or denied: the agent is `waiting`, in the needs-you inbox as asking. For Claude's own agent the board holds it and answers it with the user's answers, from the quick ask, while Claude's dialog in its terminal asks too; a subagent's is read only, with Open the agent to answer. It is settled once the call runs with its answers.
_Avoid_: permission prompt (it grants nothing), question (that is a question asked through the board, `ask`)

**Hold**:
The daemon keeping a harness's `PermissionRequest` hook open so the inbox can answer the permission prompt. Claude asks in the agent's terminal at the same time, and whichever answers first decides, so its own prompts are held until settled (a day at most); a Codex agent's or a Claude subagent's terminal waits on the hook, so theirs are held for 20 s. When the hold lapses unanswered, only the agent's terminal asks.

**External session**:
A harness session the app did not spawn (started in another terminal) but discovered through the opt-in global hooks and placed on the board: in the zone matching its folder, else in the **Unsorted** group. Its tile can be dragged anywhere, out of Unsorted too, and keeps that place; its folder only says where a new one goes. It has no terminal in the app: it can be **removed from the board** (never stopped: one still running elsewhere says so first, and comes back if it starts again), or **resumed in agent-board**, which adopts it as an agent under the same session id (`claude --resume`, `codex resume`) in its tile's place, keeping its connectors, the external tile going. It resumes in its own folder by default, an agent that doesn't own its worktree, so deleting it only takes it off the board; or, in git, in a new worktree cut from its branch; or, its folder gone, in one the user picks. The app asks first, Cancel the default, warning when that folder is the repo's main checkout, and when the session may still be running elsewhere (it never reported its end, or its transcript was written since).

**Unsorted**:
A normal **group** zone the daemon makes on demand, right of the zones and level with the topmost, for external sessions whose folder is in no zone and that haven't been placed anywhere yet (and, when the app starts, for those of a board from before it was a group). It is moved, resized, renamed, recoloured, tidied and deleted like any zone, and a tile leaves it by being dragged out. It is found by a mark the daemon keeps, not its name, so renaming it loses nothing; once it is bound to a repo, removed or deleted, the next such session gets a fresh one. Deleting it (or any zone) from its ⋯ menu or with ⌫, which the daemon does in one step, leaves its tiles loose on the board where they are drawn and never deletes a session, worktree, branch or the zone's repo folder; only a managed clone's folder can go with its zone, if asked, and not while an agent has a worktree in it.
_Avoid_: inbox (that is the needs-you inbox)

### Flows

**Edge**:
A directed link from agent A to agent B that delivers A's **payload** to B when A finishes, optionally gated by a **condition** and either automatic or manual. Drawn from a **connector handle** of one agent's tile onto another agent's tile: let go, a chooser asks **Arrow** (the default) or **Hand off** (H), and with ⌥ held while dragging it is a hand-off with no chooser (only agents' tiles take one then, and Escape calls the drag off). Made, it is selected and its **Edge rules** open. Like a connector, it leaves and arrives at any side of its tiles, straight, elbow or curved, through any bends. An end on no side the user picked (an edge an orchestrator or the CLI made, or one let go on a tile rather than on its handle) has an **automatic side**: the side of its tile facing the other tile, picked again each time it is drawn, so it follows its tiles as they move, until the user drags that end to a side. Either end can be dragged onto another agent's tile, and the edge hands off there instead, dropping what it held or queued, and, for a new sender, every approval. The edges between two agents are drawn as one **rail**, the latest document riding it as a **rail token**; they stay separate edges, each with its own rules. Kept by the daemon (`flow_edges`), and deleted with either agent. At most one joins A to B; auto edges never make a loop, as the agents would answer each other for ever. Each keeps its history: what it delivered, skipped (and why), **held** and released. Its token says when it last delivered ("delivered 14:02"), and its Edge rules show what that hand-off carried, while the daemon remembers it. Making, reshaping, moving an end, making one from an arrow, or deleting one can be undone. An **agent-made** edge is one an orchestrator made: its token says who made it, and it is the user's to change or delete like any other.
_Avoid_: connection, wire; a **connector** is the whiteboard annotation, which carries nothing

**Rail**:
How the board draws the edges between two agents: one faint dashed line, whatever its edges' rules. Two agents with edges both ways (a **linked pair**, such as an implementer and its reviewer) have a rail with no arrowheads; one way only, it has a small open arrow at the receiving end. It takes the shape of the edge made first between them, and is reshaped as an edge is, automatic sides and all. A click on it or its token selects the edge its token is from, opening that edge's **Edge rules**, where a switch, naming each by its ends ("Fix it → Review it"), picks between a rail's edges. Its ends are its tiles' sides; an end dragged onto another agent's tile moves every edge on it to that agent. The hand-offs-only connections view shows rails, and none hides them, the tile's count badge counting a rail once.
_Avoid_: two arrows, lane

**Rail token**:
The latest document on a **rail**, at the end of whoever has it: its name (`review.md`, `final message`), a linked pair's round (R1, R2: how many times its edge has delivered, counting one on its way or waiting) and a line under it. In order: a hand-off on its way slides to the receiver ("sending…"; drawn there at once under reduced motion); one **held** at the sender says what for ("held until CI green") and how many of its conditions pass (1/2); one queued, or waiting for Send (in the waiting colour, with ▶ send), sits at the sender; else the last delivered rests at the receiver ("delivered 14:31"), or a skipped one at the sender ("skipped"); before anything has gone, a dashed ghost at the sender says what comes next ("when done", "on send", "on CI green"). A manual edge waits for Send while its agent sits done with its turn and that turn ended after the edge last delivered (or before its first delivery): the daemon keeps when each agent's own turn last ended (`Agent.finishedAt`), across restarts. A **one-off edge** never waits: its agent hands off along it mid-turn, and Send would only replay it. A paused edge says so on its token, whatever it holds. Tokens off the same side of one tile are spread apart, in the order the tiles at their rails' other ends lie. On a rail too short for it, the token shows its mark, round and Send alone, the rest on hover or focus. It moves with its tiles at once, and eases only on its slide from one end to the other.
_Avoid_: token alone (a **Token** is a tile representation), chip, label, payload chip

**Continue on credits**:
Resuming the turn of a Claude agent its usage limit stopped (`rate-limited`), for its usage credits to pay for, as the user would in its terminal: the tile's menu item and the button on its rate-limited pill, `agent-board continue <ref>` and the MCP tool `continue_on_credits` (`agent.continueOnCredits`). Offered only while it is rate-limited, and never done by itself: the user or an orchestrator chooses it. It takes the step Claude offers: the menu Claude opens on a rate limit ("What do you want to do?", known by its title, its rows or a numbered option under its pointer, read from the bottom of the screen up so what is above the prompt is history) is closed with Escape, its cancel, which picks no row, so never one that opens a billing or upgrade page, and leaves Claude's own continue at the reset armed; then `continue` at its prompt, as Claude puts there itself to carry on at the reset, and Enter, again while no turn starts. It answers once the turn starts, and refuses, saying why, an agent that is not rate-limited (checked again when its turn to be typed at comes, so a second ask is refused), runs Codex, holds an **unsent message**, has the user typing at its prompt or other text there, or shows neither screen. A turn the limit stops again at once means its usage credits are spent too.
_Avoid_: nudge, auto-continue (Claude's own wait for the reset)

**Unsent message**:
A hand-off, scheduled run or message the board typed at an agent's prompt whose turn never started, however often Enter was pressed (`Agent.unsent`). Its tile says so ("Hand-off from impl not sent") with **Send**, which presses Enter again, its orchestrator hears `not-sent`, and the user is flagged with why it was given up on (no turn started after the last Enter, they typed there meanwhile, or it moved on first), a flag that stays, opened or not, until it is sent or cleared; a flag the agent already had goes on in its reason, and stands again after. One the agent raises after it stands in its place, and once that is cleared or read away the unsent flag stands again. Nothing more is typed at that prompt (deliveries are skipped as busy, a queued one waiting) until it is sent, submitted or cleared in the terminal, or the session ends. An orchestrator that may steer the agent sends or clears it too, never while the user is typing there (`agent-board send <ref> --submit` or `--clear`, the MCP `send` tool's `submit` or `clear`), and an orchestrator's `send` whose message is left so says it was typed but not sent, never that it was sent. A message sent while the agent works, or anything typed at one that starts a turn before its Enter, gets one Enter, which its harness queues for after that turn. If no turn of its own starts once that turn ends (or fails), Enter is pressed again, and then it is unsent too. One whose turn was interrupted, from the board or in its terminal, is unsent at once, without Enter, as the harness may have put it back at the prompt; so is one whose turn hit a rate limit, as the harness may show a menu then, and the user is flagged for it. A prompt the user submits, or Enter or Ctrl-U they type, makes it theirs, never the board's unsent message. Nothing is typed at all once a permission prompt, a question or a rate limit is up, where its keys would answer that: a message waiting its turn behind another delivery is refused then, saying why, and stays with whoever sent it; a rate-limited agent goes on with **Continue on credits**.
_Avoid_: stuck hand-off, undelivered (it was delivered: it sits typed at the prompt)

**Waiting message**:
A message another agent sent an orchestrator (the Captain, or a zone's lead) mid-turn, kept by the daemon until that turn ends, then typed at its prompt as a turn of its own, oldest first (`Agent.messagesWaiting`; `send` says `queued-after-turn`). Its tile counts them ("2 messages waiting"). Never typed into a turn, a question or a permission prompt; if its session ends or the daemon shuts down first, each is handed back as not delivered, for the user's Resend.
_Avoid_: queued-in-turn (a message the harness itself holds, typed with Enter as a turn ran)

**Hand-off**:
An agent passing on its payload: **explicitly**, by calling `agent-board handoff` or the Board MCP's `handoff` tool (`board.handoff`), along its own outgoing edges (or one, `--to`), or, naming an agent in its scope it has no edge to, over a **one-off edge**, each taking the part of what it hands over that matches what the edge carries (a message, a handover file, JSON); or **inferred**, its own turn ending with a final message (its `Stop` hook's `last_assistant_message`), along the auto edges it didn't hand off along explicitly that turn. Every hand-off goes the same way: along each of the agent's auto edges, each carrying its own payload as it is at that moment, delivered to B as its next message, as a scheduled run's prompt is (one line, so a multi-paragraph message arrives joined), and relaunching B if its session has ended. It arrives headed with A's **sender mark**, then "Hand-off from A (its final message):" (or with the payload's own name, "(its plan.md):", or "(its review, round 2):" for a review doc), with no control characters, so another agent's words never start as one of B's commands (`/`, `!`) or drive its terminal. A delivery to a B that is still working, rate-limited, showing you a permission or question prompt, or being typed to is skipped, saying why, unless the edge delivers by **queue after turn**: then it waits until B's turn ends (tried again every minute too), a newer one replacing it. A paused edge delivers nothing by itself. An edge with **conditions** checks them first, and **holds** the hand-off while any fails. A B whose last message asked you something still takes it: the hand-off is its next input. A delivery has landed once B's turn starts (its `UserPromptSubmit`): Enter is pressed once B's harness has drawn the text, and again, waiting longer each time, while no turn starts and B's prompt holds only that text, as a slow machine's harness can lose an Enter. One still not submitted after that is **unsent**. A shows `handing-off` until its deliveries have landed, unless it is waiting for you, which it goes on showing. An edge's Send delivers its payload as it is now (A's last final message, which outlives a daemon restart, or its file) the same way, whatever its conditions say, dropping any held hand-off. On the board, a hand-off shows along its edge for at least a moment, however soon it landed: its **rail token** slides along the rail to B, A's robot hands it on, and B's tile reads "receiving…" (a look, not an agent state). A skipped delivery shows nothing travelling.

**Sender mark**:
What heads every message the board types at an agent's prompt for another agent, on its first line: `⟨send from Captain · agent:944e1234⟩` (ADR-0023). It names how it came (`send`; `reply`, an answer to the receiver's message, flag or question; `hand-off`), the sender's name and its ref. The receiver reads it; the chat reads it back from the transcript, which holds every message as the user's, so another agent's message is never shown as one the user typed (`ChatEntry.from`). The user's own messages carry none.
_Avoid_: sender marker, trailer (the closing `[agent-board] From …` line a message may also end with)

**One-off edge**:
The edge a named hand-off makes (`agent-board handoff --to` an agent it has no edge to; `FlowEdge.oneOff`): manual, marked as made by the agent, delivered along at once, and named again it hands off along it. It keeps what it last carried, which its Send replays, after a restart too. It never starts an ended agent again (only the user's Send, or an edge the user drew, does), so two agents naming each other back and forth never relaunch each other; a reply by name is never refused.

**Edge rules**:
The panel on the right of the board for the **edge** selected, opened on a new one as soon as it is drawn, the board panning clear of it. Under its ends, four sections, each opening with a line saying what it does: **When** (its trigger, and whether it skips a busy B or waits for its turn, as queue after turn), **What** (its payload and file, and a preview of what it would carry now), **Only if** (its **conditions** with how each last checked, and Approve in place for a gate or script not yet approved) and **History** (what it holds, what it did, what it last carried). Its footer has Pause (a paused edge's auto hand-offs are skipped and what it holds or queued waits; Send still sends), Delete and Send now, which says how it went: sent, queued until B's turn ends, or why nothing was sent. A reviewer started on an agent's branch gets no edge to it unless `new --edges` asks for one: they talk through `send`.
_Avoid_: edge popover, edge settings

**Payload**:
What an edge carries: A's final message, a markdown file from A's worktree (`handover.md` unless set, such as `plan.md`), or a JSON file from it (`handoff.json` by default), checked to be JSON and sent on one line. A file must be inside A's worktree, through any link, and at most 64 KB; one missing, too big or not JSON is skipped, saying why.

**Condition**:
What must hold before an auto edge delivers a hand-off; all of an edge's must pass. **Gate green**: a gate command (`pnpm check:local`) passes in A's worktree, run again only once A commits, one run shared by every edge asking, and only once the edge's other conditions pass. **PR checks**: the checks of A's newest pull request pass. **Issue label**: A's linked issue has the label. **Custom script**: a command exits 0 in A's worktree. A gate or script runs only once you **approve** what it runs, shown whole: the command, the `package.json` script it names, and the files they name, by hash. If any of those change, it waits for your approval again (ADR-0009).
_Avoid_: rule (the rules are all of an edge's settings), filter

**Held**:
A hand-off an edge keeps, as it was read when A handed off, until its conditions pass: checked again every minute, whenever A's pull requests change, and when its conditions do, then delivered. A newer hand-off replaces it, Send delivers now instead, and changing the edge's payload, or making it manual, drops it. A paused edge keeps it until resumed. Its **rail token** says what it is held until ("held until CI green"). A held (or queued) file is kept as a copy until it is delivered, or, if Settings says **path only**, read again when it is delivered (ADR-0009). Drop in the Edge rules throws it away.
_Avoid_: queued (a queued delivery waits for B's turn to end, by **queue after turn**, not for conditions), pending

**Reviewer**:
An ephemeral agent spawned from an implementer's tile (its ⋯ menu, under Review & gate, or the Review tab's Start round) to review its work: in the implementer's harness and zone, on a branch of its own from the tip of the implementer's branch (`<branch>-review-r1`), told to review the diff since the commit the implementer started from, change nothing, and reply with only its review doc. Its tile is dashed. Once its doc is in, it is stopped (`done`); the next round, or dismissing its round, deletes it and its worktree.
_Avoid_: review agent

**Review doc**:
What a reviewer leaves behind: its final message, markdown with a title, a `Verdict:` line (only `Approve` or `Changes requested` count; anything else approves nothing) and findings under `## Blocker`, `## Major` and `## Minor`, each a **bold** title, a `path:line` and why; one a later round finds fixed has its title struck through. Kept by the daemon with its round, shown in the implementer's session window, on a **Review** tab beside its terminal: the rounds on the left, the doc in the middle (its verdict and findings by severity with file:line chips, or the markdown as it is when not in that format), and its actions on the right. **Send to implementer** delivers it as a hand-off (`Hand-off from <reviewer> (its review, round N): …`), skipped as any hand-off is when the implementer can't take it now; **Approve and merge** squash-merges the implementer's open pull request, from the latest round only, once it approves with no open blocker and the PR's checks, looked at again first, aren't pending or failing; and only at the commit the round reviewed, so nothing pushed since is merged. Dismissing the latest round closes its tab; asked for from the tile, it opens again, with every doc.

**Review round**:
One numbered review of an implementer's work: its reviewer and the commit it reviewed, and then its doc, or why it has none (the reviewer ended first, or was deleted or dismissed before it left one). Rounds are kept per implementer, one at a time, at most its **review cap** of rounds that left a doc (3 unless set, 1 to 10, from the Review tab's rail), and go with it. A later round's reviewer is given the last doc, to say what was fixed.

**Trigger**:
What starts a long-lived agent run: a cron schedule or a webhook.

**Run**:
One time a clock fired, kept in its run history: sent, skipped (and why), running, done (with a fresh agent's final message) or failed. A scheduled run sends the clock's prompt to the agent's session as its next message, relaunching the agent first if its session has ended; a fire time at which the agent is still working, rate-limited, waiting for you, or being typed to, is recorded as skipped, as is one while the clock's last run is still going. A fresh agent's run fails when its agent fails, ends or goes before its turn does; one the app stopped during says so, and its agent is closed or kept as its clock says.

### Infrastructure

**Daemon**:
The background process (`agent-board daemon`) that owns sessions, PTYs, the database, the scheduler and the webhook listener. Every screen is its client: the app's windows and the CLI over its Unix socket.

**Terminal backend**:
Where a session's terminal lives. v1 has only the built-in PTY.

**Tracker**:
An issue-tracker provider behind a common interface: Linear or GitHub Issues. Each zone picks one, and a scope in it.

**Scope**:
Where a tracker's issues live, and what a zone is bound to: a Linear **team** (keyed `ACME`) or a GitHub repo (`owner/repo`). "Scope" is the provider-neutral term in code and the API; the UI uses the provider's own word ("team", "repo").
A tracker scope can be narrowed to one **project** of it (a Linear project, kept by its ID): the zone's issue picker then lists only that project's issues. GitHub has none.
_Avoid_: project (for a scope: a Linear project is a part of one)

**Linked issue**:
The tracker issue an agent works on, shown on its tile. Kept as a snapshot (provider, ID, title, URL) taken when it was linked or the agent was started from it. Linking never renames the agent's branch; starting from an issue names it (`acme-12-…`, `gh-34-…`). A GitHub issue's ID is `owner/repo#34`, shown as `#34`.

**Tracker credential**:
The API key or OAuth token agent-board uses for a tracker. Lives only in the OS keychain (service `agent-board`, account = provider), never in the database. GitHub has none: agent-board uses the `gh` CLI's own login.

**Pull request** (PR):
A GitHub pull request whose head is an agent's branch, shown on its tile with its state (open, draft, merged, closed) and its checks (passing, failing, pending). Found for every agent whose repo is on GitHub, whatever its zone's tracker. Its chip opens it in a **PR tab**. Only these are the agent's own, which its header's Merge, its gate and its clean-up act on. An agent with none of its own also shows, marked with an arrow ("Pushed to #174"), the pull requests its work went into on other branches: those of the branches it pushed its own commits to (its branch's upstream among them), else the one holding its newest pushed commit. These are only shown: nothing is merged, gated or cleaned up from it, and an agent with a pull request of its own doesn't look for them.

**PR tab**:
A **surface** showing one GitHub pull request, drawn by the app from what the daemon reads with the user's own `gh` login, with no web content loaded: its description (Markdown, nothing in it loading, its links opening in the OS browser), its checks, its changed files each with its diff (the first 100; a diff too large is left out), and its reviews and comments. It opens from an agent's PR chip (on its tile, its expanded tile's header), the PR and checks rows of its details, its Review tab, and its window's + menu, in the focused pane, or shows the PR tab already open there. It drags and splits like any tab, closes with its ×, and is kept in the window's layout by repo and number across restarts. It reads the pull request as it shows, as the app is focused while it shows (at most every 15 seconds), and on Refresh, never on a timer; a tab not showing never reads it. A failure, GitHub's rate limit among them, is said in the tab. **Approve** and **Squash and merge** show only while GitHub would allow them (open, not a draft; approving not one's own; merging with write access, in a repo that allows squash merges, with no conflicts and nothing blocking), else why not. Each asks first, and each takes only the commit shown: if anything was pushed since, nothing is approved or merged. Done but not read again, it says so and offers nothing more until it is. On an agent's pull request in a zone with a **gate command**, its Squash and merge is disabled ("Merge from Fix checkout flake's window header: it waits for the gate.", naming the agent), in any window, and the daemon refuses it: the header's Merge is the one that waits for the **merge gate**. Agents can't do either (ADR-0010).
_Avoid_: PR viewer, PR panel

**Merge gate** (gate):
The check that an agent's work is fit to merge: its zone's **gate command** run in the agent's worktree, only ever when the user clicks Run gate (the details strip's Gate section, ⌘⇧G, the tile's ⋯), never by the app. Its **gate run** is kept per agent, the latest only, with its logs per agent and commit; it passes on the commit its worktree was at as it started, unless it had uncommitted changes then or the worktree changed while it ran. **Merge** sits in the agent's session window and expanded tile headers in every zone, once the agent has an open pull request; the headers have no Open PR button (removed: agents open their own). The agent-side open (`agent-board open-pr`) waits for nothing uncommitted (the agent's `.agent-board/` notes aside) and, in a zone with a gate command, a pass on the worktree's head; it pushes that commit (never forced) and has gh open a draft pull request titled after its issue (or its name), its description the repo's pull request template filled from the agent's `.agent-board/handover.md` (its closing keywords defused), with the gate table under How to verify in a gated zone and `Fixes <issue>`. **Merge** squash-merges it only once GitHub's checks are green and, in a gated zone, the gate passed on the pull request's head, both checked again by the daemon, at that head alone; in a zone with no gate its popover says so. It then cleans up as its boxes say: close the agent, remove its worktree and delete its branch (here, then on GitHub) only while the worktree holds nothing but what was merged, and comment on its issue. A clean-up step that fails or is kept is said; the merge still happened. A gated agent's pull request is merged from its header alone: a PR tab's merge of it is disabled, and the daemon refuses it, even before the agent's pull requests are read (by its branch, else by its repo). For a pull request that isn't the user's own, the header offers **Approve** instead. Agents can't run the gate, open a pull request or merge from it (ADR-0010).
_Avoid_: CI, check (a check is GitHub's)

**Gate command**:
A zone's setting: the command its agents' merge gate runs, such as `pnpm check:local`, or none. It runs through `sh -c`, so `&&`, a pipe or `$VAR` work as in a terminal. It marks its steps by printing lines like `::gate start lint` (ADR-0013); a command that marks none is one step, named after itself.

**Gate run**:
One run of an agent's gate command: the commit it ran on, whether that had uncommitted changes, its steps in order (waiting, running, passed, failed or stopped, each with its times) and how it ended (passed, failed, or stopped by Stop, which ends its whole process tree, or by the daemon going away). A step's log is its own lines, or the file it named; the whole output is kept too, each log up to 10 MB. The tile's footer says it in a word (`gate 3/5 · test`, `✓ gate 5/5`, `✗ gate · e2e`).

**Gate tab**:
A **surface** showing an agent's latest **gate run**: its headline, command and commit, its steps as a table, and the picked step's log under it, following the running step until another is picked; Stop, Run again, and on a failure "Send failure to" the agent, which pastes the failing step's last lines at the agent's prompt without sending them. A run on an older commit than its worktree's head, or with uncommitted changes, is greyed and says so. It opens in the focused pane, drags and pops out like a PR tab, and closing it keeps the run.

**Tab window**:
A popped-out OS window that is no session's (slice 4): where a pull request or web tab dragged out of every window goes. It lays out pull request, web and session tabs in panes as any session window does, and they drag in and out of it as from any window; a shell can't be dropped in it (it has no owner for one), and it has no details. It closes once its last tab leaves, and closing it closes its tabs. It is kept across restarts, popped out again, as other pop-outs are, and one the board lost track of (the app quit as it popped out) pops out again as the board opens; ⌘Z puts a tab popped out into one back, and the tab window closes with it.
_Avoid_: detached window, floating tabs

**Web tab**:
A **surface** showing a web page, mainly an agent's dev server on this machine: a page the app draws in a locked-down web view of its own over the tab's area, under an address row (back, forward, reload, its URL and Open in browser). It shows only https pages and plain http ones on this machine (`localhost`, `127.0.0.1`, `[::1]`), never a `file:`, `data:` or `javascript:` page; every navigation and redirect is checked, and one stopped is said in the tab. Its page has no Node, no preload and no devtools, runs sandboxed in the session web tabs share, kept on disk so its logins, cookies and storage outlast the tab and the app as a browser's do (Settings › Advanced › Web tabs: **Keep logins between sessions**, on by default, and **Clear browsing data…**; off, every web tab is private, those open then made again so, signed out) (ADR-0020), shows no alert, confirm or prompt, opens no window (an https page it asks to open is offered under the address row, and opens in the OS browser only on a click), is granted no permission (camera, microphone, notifications, location…) and downloads nothing. A page that explicitly asks for a **passkey** can't be served one on macOS (Electron has none for an arbitrary site: system passkeys need the site to list the app, and Touch ID ones need a signed app and outlast no tab's session), and its request is left pending: the tab says so under the address row as it asks, with **Open in your browser** (which also dismisses it) and Dismiss, back if the page asks again; the dismissal stays with the tab as it moves between windows. A request for autofill is passive and says nothing. It learns of the request from a small script it runs in the page once the page is ready, which wraps the page's credential calls, reads only whether they ask for a public key and logs to the console under a secret of the tab's own; a page can tell it is there, and a request made before the page is ready or inside a frame in it goes unseen. Only a page on this machine reaches this machine: an https site in a web tab can't fetch from a local server or open a socket to it, and sends the tab there only by a link the user just clicked, never by a form or a script. A page never asks "Leave this page?". It opens from the + menu's **Web…** (an address to confirm, the port a shell of the window listens on, else `localhost:3000`, filled in) or a ⌘-click on a local address in a terminal's output (Ctrl off macOS), in the focused pane, or shows a web tab already at that address. It is named after its host (`localhost:5173`), drags and splits like any tab, and is kept in the window's layout by where its page was last at for a moment, without its query or fragment (which may hold a sign-in's code), and loads it afresh at the next start. Its page follows its pane as it moves, and goes as it is, never reloaded, with its tab to another window, or with its window popped out or back in, and is hidden while its tab isn't showing, while a menu, a dialog or another window is over it, and while something is dragged across it. The window's keys (⌘W, ⌘T, ⌘D, ⌘1–9…) work from the page as from anywhere in the window, and ⌘R (⇧⌘R past its cache) reloads the page. Closing it ends its page, as does its window closing. A **private** web tab, from the + menu's **Private web…**, runs in a session of its own, in memory, whatever the setting: closing it, or its window closing, forgets its cookies and storage. Its address row says Private, as does any tab whose page is private because the setting is off or couldn't be read. Agents can't read, drive or screenshot a web tab; a link they pin or print opens in one, signed in, on the user's click, and the address a tab ends up at (without its query) is in its window's layout, which they can read.
_Avoid_: browser tab, webview

**Status file**:
`.agent-board/status.json` in a worktree, written by harness hooks; the contract between workers and whoever supervises them. It names its writer's `session_id`, so an external session's tile shows the state, summary and doc paths only for the session that writes it (`StatusFile` in the protocol).
_Avoid_: worker status
